# Wrap unmodified Claude Code in a trustworthy companion

*Technical research for Companion (working name), Curious path. State of the world as of 6 October 2026. Location in the repo: `docs/research/technical_research.md`; read `docs/research/product_research.md` first for what each feature must do. Written to be read by Claude Code at the start of the build. Items marked **[verify]** come from prior knowledge or secondary sources and must be checked in a spike before code depends on them.*

Build Companion as three local processes and one tiny cloud service. A **Tauri 2.12 shell** (Rust plus a React UI inside non activating macOS panels) owns windows, focus, hotkeys, secrets, permissions and everything that touches the operating system: the edge dock and characters, the pointer overlay, reading and pasting text in other apps, one shot screen capture, on device text recognition, the microphone and on device transcription. A **long lived TypeScript runner**, compiled with Bun and shipped as a Tauri sidecar, owns agents, safety, checkpoints, proof, ship, memory, the local task log, scheduled jobs and the relay connection. The **unmodified, Anthropic signed Claude Code binary** does the model work, driven by the runner through the Claude Agent SDK (`@anthropic-ai/claude-agent-sdk` 0.3.291, which bundles Claude Code 2.1.291): full agent sessions for Build mode, a warm "fast lane" for small text jobs (Prompt help, Where was I, recaps), and a tool restricted vision session for Show me how. A stateless **relay** carries only ciphertext to the phone. The engine is "bring your own Claude": an API key in the OS keychain (the polished default), a cloud credential, or the user's own subscription signed in through Anthropic's own `claude auth login` flow, which waits on Anthropic's written confirmation. Companion never shows a claude.ai login, never touches tokens and never pays for usage ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance), checked 6 Oct 2026). Everything that makes Companion trustworthy lives outside the engine: safety enforced in `PreToolUse` hooks and deny rules, whole tree snapshots in a Companion owned shadow git repo, a proof ladder of exit codes before any vision judgment, approvals bound to a checkpoint and a single tool call, hotkey only access to the screen and other apps' text, and memory the user can read and edit. The riskiest unknowns are packaging the sidecar with Anthropic's binary, panel and overlay behaviour over full screen apps, reading and pasting into other apps reliably, pointer accuracy, fast lane latency, and Anthropic's wording on subscriptions; milestone M0 exists to retire them before feature work.

## 1. The architecture in one paragraph and fifteen decisions

Companion is a supervisor, not a model wrapper. The shell owns windows, focus, hotkeys, secrets, OS permissions and updates; it is also the only component allowed to read the screen, read or paste text in other apps, or open the microphone, and it does so only on a user hotkey. The runner owns agents, safety, checkpoints, proof, ship, memory, the task log and the relay connection, and it speaks a versioned JSON lines protocol so it can be tested headless (the prototype already proved this pattern with `node runner/index.mjs step ...`). Claude Code does the agent work inside the user's project folder. The table lists the decisions a builder needs before writing code; each is expanded in its own section.

### What the prototype taught

The `companion-alpha` prototype (Tauri 2 + React, Node runner on SDK 0.3.291, eight passing safety net tests) validated the core loop and exposed five design errors worth fixing on day one. First, its outside the folder guard for `Write` and `Edit` lives in `canUseTool`, but with `permissionMode: "acceptEdits"` and those tools in `allowedTools`, the SDK approves them before `canUseTool` is ever called, so the guard is dead code; the SDK evaluates hooks, deny rules, ask rules, the permission mode, allow rules and only then `canUseTool` ([SDK permissions](https://code.claude.com/docs/en/agent-sdk/permissions)). Second, `ensureRepo` runs `git init` and `git add -A` plus a commit inside a non git folder, which writes into the user's history and, without a `.gitignore`, commits `.env` and `node_modules`. Third, `restoreCheckpoint` ends with `git reset -q`, which silently discards whatever the user had staged. Fourth, each step spawns a fresh `node` process with a single string prompt, so there is no session continuity, no interjection mid run and a cold start every step. Fifth, the Tauri capability grants `shell:allow-spawn` for `node` with `args: true` and the CSP is `null`, which means any script injected into the webview could run arbitrary Node code. Keep the event vocabulary, the temporary index technique, the receipt and the friendly copy; move spawning into Rust, safety into hooks, snapshots into a shadow repo and the agent into a long lived streaming session.

Trust boundaries drive the layout. The webview is the least trusted component, so it can only call named Rust commands; it never spawns processes, never receives secrets, and never holds full resolution screenshots or text read from other apps beyond what the card displays. Rust reads the API key from the keychain and injects it into the runner's environment at spawn. Rust is the only component that touches the screen, other apps' text, the microphone and OAuth; it hands the runner only redacted, resized images, transcribed text and the text it read for the current request. The runner is the only component that talks to agents, git and the relay. The relay sees ciphertext, push subscriptions and timing, nothing else.

### JSON lines protocol, version 1

Every line is one JSON object with a common envelope: `v` (protocol version), `id` (unique, for acknowledgements and dedupe), `ts` (ISO time), `project` (stable project id derived from the folder path, when relevant), `agent` (agent card id, when relevant) and `type`. Commands go UI to runner on stdin; events go runner to UI on stdout; stderr is a log stream only. The runner must flush whole lines and the Rust side must buffer partial chunks (the prototype's `runner.js` already handles split chunks; keep that logic, but in Rust).

## 3. Engine layer: the Agent SDK with hard limits and no credential handling

### The SDK configuration to start from

```ts
import { query } from "@anthropic-ai/claude-agent-sdk";

const session = query({
  prompt: userMessages,                       // AsyncIterable<SDKUserMessage>, fed by agent.send
  options: {
    cwd: projectDir,
    pathToClaudeCodeExecutable: claudeBinPath, // the separately shipped, Anthropic signed binary
    env: buildChildEnv(),                      // REPLACES the environment: spread process.env yourself
    settingSources: ["project"],               // load project CLAUDE.md and rules, not ~/.claude user settings
    strictMcpConfig: true,                     // only mcpServers passed here: no claude.ai connectors, no .mcp.json
    systemPrompt: { type: "preset", preset: "claude_code", append: COMPANION_APPEND },
    permissionMode: "acceptEdits",
    disallowedTools: SCOPED_DENY_RULES,        // e.g. "Bash(git push*)", "Bash(sudo *)"
    hooks: { PreToolUse: [safetyHook], PostToolUse: [ledgerHook], Stop: [proofTrigger] },
    canUseTool: routeToApprovalUI,             // only for calls that fall through
    sandbox: { enabled: isMac, allowUnsandboxedCommands: false },
    maxBudgetUsd: card.budgetUsd,
    maxTurns: 80,
    model: "claude-sonnet-5-5",
    enableFileCheckpointing: true,
    extraArgs: { "replay-user-messages": null },
    includePartialMessages: true,
    abortController,
    stderr: (line) => log.debug(line),
  },
});
```

Each option has a reason. `env` replaces rather than merges, so `buildChildEnv()` must start from `process.env`, set the user's login shell `PATH`, set `CLAUDE_AGENT_SDK_CLIENT_APP` to identify Companion in the User Agent, add `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` so memory stays in visible files, add `DISABLE_UPDATES=1`, which Anthropic advises when you distribute Claude Code through your own channels, so the bundled copy never updates or replaces itself, and add `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` ([TS reference](https://code.claude.com/docs/en/agent-sdk/typescript); [Claude Code features](https://code.claude.com/docs/en/agent-sdk/claude-code-features); [Setup](https://code.claude.com/docs/en/setup); [Env vars](https://code.claude.com/docs/en/env-vars)). Without the scrub, the `ANTHROPIC_API_KEY` that Rust injects reaches every command the agent runs: the scrub strips credentials from the subprocesses Claude Code starts, such as Bash commands, hooks and stdio MCP servers, while Claude Code keeps them for its own API calls; it leaves GitHub tokens and proxy settings in place ([Env vars](https://code.claude.com/docs/en/env-vars)). The runner's own spawns (dev server, Playwright, gitleaks, package installs it runs itself) get an env with no `ANTHROPIC_*` keys at all. Omitting `settingSources` loads user, project and local settings, including the user's personal hooks and permissions from `~/.claude`; `["project"]` still loads the project's `CLAUDE.md` and `.claude/rules` ([Claude Code features](https://code.claude.com/docs/en/agent-sdk/claude-code-features)). `settingSources` does not control everything: managed policy, the global `~/.claude.json`, the user's sandbox credential deny entries and auto memory are read anyway, and claude.ai MCP connectors (the user's mail, drive and so on) load whenever the session is signed in with a claude.ai login, even with `mcpServers: {}`. So `strictMcpConfig: true` is required in agent sessions, the fast lane and the vision lane; it matters most on the plan route, and `ENABLE_CLAUDEAI_MCP_SERVERS=false` in `env` is only an extra layer, not a substitute. It also ignores the project's `.mcp.json`, so pass any project MCP servers the user approved (section 8) through `mcpServers` ([Claude Code features](https://code.claude.com/docs/en/agent-sdk/claude-code-features)). The `claude_code` preset with `append` keeps Claude Code's tested agent prompt and adds Companion's persona and rules; omitting `systemPrompt` gives a minimal prompt, not Claude Code's ([TS reference](https://code.claude.com/docs/en/agent-sdk/typescript)). Pin the exact SDK version in `package.json` (no caret) because each SDK patch moves the bundled Claude Code version and npm showed SDK 0.3.291 and CLI `latest` 2.1.291 against `stable` 2.1.285 on 6 Oct 2026 ([npm SDK](https://registry.npmjs.org/@anthropic-ai/claude-agent-sdk); [npm CLI](https://registry.npmjs.org/@anthropic-ai/claude-code)). SDK 0.3.292 (Claude Code 2.1.292) shipped later that day; keep the 0.3.291 pin for M0 so every spike matches, and always run the SDK's bundled binary, never a `claude` found on `PATH`.

### Auth: detect, guide, never touch

Anthropic's legal page says products that run Claude Code may not modify the binary or disable its auth methods, may not "pay for, resell, or intermediate Claude usage", and that each end user authenticates with their own API key, subscription or cloud credential; developers "may not collect, store, or intermediate Claude.ai credentials or session tokens", while an end user signing in to "the unmodified Claude Code binary with their own Claude subscription" is not prevented ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)). The same page tells developers building products, including with the Agent SDK, to use API key authentication through Claude Console or a supported cloud provider, so the API key and cloud credential are the routes Anthropic tells SDK developers to use; the plan login waits for Anthropic's written yes (see "One tension" below). The flow, with the API key route presented first in the UI because it needs no confirmation:

1. Detect at first run, at launch and for routine checks through a dedicated long lived streaming `query()` whose prompt iterable has not yielded anything yet, started with the same binary, env and config folder that agent sessions use; then read `accountInfo()` or `initializationResult()` and `system/init` (step 5). Nothing reaches the model, so this spends no tokens, and because the process stays alive, any token refresh it starts finishes and is saved. It is not the warm fast lane handle: a `startup()` `WarmQuery` has only `query()` and `close()`, and `accountInfo()` lives on `Query`. On the API key route the same query confirms which key source is really in use (`apiKeySource`), even though fast lane jobs may skip the subprocess. Whether it works when the user has no login at all is checked in spike (c). Run `<claudeBinPath> auth status` only while waiting for the Terminal sign in (step 2), when the user presses "Check again", and in diagnostics; never at first run or launch, and never on a background timer. It is not free of side effects: when the stored access token is expired or close to expiry, a short lived command like `auth status` starts a token refresh and can exit before the new token is saved, which signs the user out (open bug [#95822](https://github.com/anthropics/claude-code/issues/95822), a user report with a repro; track it). After a night the access token is usually expired, so a first run check with `auth status` could sign out a user who already had a working login. `auth status` prints JSON, exits 0 when logged in and 1 when not, reports `authMethod` as one of `none`, `claude.ai`, `oauth_token`, `api_key`, `api_key_helper` or `third_party`, and since Claude Code 2.1.268 adds `configDirectory`, the config folder it used ([CLI reference](https://code.claude.com/docs/en/cli-reference)). Show four states: **Plan** (`claude.ai`, `oauth_token`), **API key** (`api_key`, `api_key_helper`), **Cloud** (`third_party`) and **Not connected** (`none`), plus **Unknown** with the raw JSON in a details panel for any other value. Use the same binary and the same config folder that agent sessions will use, otherwise detection and use disagree ([Authentication](https://code.claude.com/docs/en/authentication)). Leave `CLAUDE_CONFIG_DIR` unset in `auth status`, the Terminal sign in, the detection query and agent sessions, and never set it to its default path `~/.claude`: Claude Code keys the macOS Keychain entry to an explicitly set folder, so an explicit default reads a different entry and `auth status` flips to `none` (open bug [#92252](https://github.com/anthropics/claude-code/issues/92252), user report). If the user's login shell already exports `CLAUDE_CONFIG_DIR`, adopt that exact value everywhere and say so in the UI, and compare `configDirectory` with the folder the SDK session reports.
2. "Use my Claude plan": open Terminal running `<claudeBinPath> auth login`, which completes in Anthropic's browser flow. Do it by writing a `.command` file and opening it with `open`, which makes Terminal run it in a new window through Launch Services with no Automation permission; driving Terminal with AppleScript `do script` would need Automation consent and the apple-events entitlement (secondhand, [scriptingosx](https://scriptingosx.com/2022/04/launching-scripts-2-launching-scripts-from-finder/)) **[verify]** in spike (c). The `.command` runs a login shell that loads `~/.zshrc`, so the script must unset every variable the runner strips (step 4) so the sign in lands in the slot Companion reads. While it waits for this sign in, and only then, Companion runs `auth status` every 3 seconds and stops at the first signed in result or after 5 minutes; it never polls in the background otherwise. It never reads `~/.claude/.credentials.json` or the Keychain item Claude Code writes.
3. "Use an API key": a native secure field in Rust writes the key to the Keychain (`keyring` 4.2.0, or `keyring-core` with `apple-native-keyring-store` as its maintainers now recommend; **[verify]** how Keychain prompts behave for unsigned dev builds); Rust passes it as `ANTHROPIC_API_KEY` only to the runner, and the runner only to Claude children, with `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` set so the commands those children start never see it (see the SDK configuration above).
4. When the user chose their plan, **delete** from the child env `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_PROFILE`, `ANTHROPIC_FEDERATION_RULE_ID`, `ANTHROPIC_ORGANIZATION_ID`, `ANTHROPIC_BASE_URL` and every `CLAUDE_CODE_USE_*` provider flag (`BEDROCK`, `VERTEX`, `FOUNDRY`, `ANTHROPIC_AWS`, `MANTLE`), and make sure no loaded settings source supplies an `apiKeyHelper`. The full precedence is: cloud provider, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY`, `apiKeyHelper`, `CLAUDE_CODE_OAUTH_TOKEN`, Anthropic profile or federation credentials, then the `/login` subscription; a signed in Claude apps gateway session outranks all of them, and in non interactive mode a present key "is always used" ([Authentication](https://code.claude.com/docs/en/authentication); [Env vars](https://code.claude.com/docs/en/env-vars)). A stray key in a user's shell profile would otherwise silently bill their Console account (one user report describes $447 billed to the API instead of a Max plan, [#62338](https://github.com/anthropics/claude-code/issues/62338)).
5. After `system/init`, read `apiKeySource` and call `accountInfo()` (`email`, `organization`, `subscriptionType`, `tokenSource`, `apiKeySource`) to show "Using your Claude Pro plan" or "Using your API key" in the receipt ([TS reference](https://code.claude.com/docs/en/agent-sdk/typescript)). `apiKeySource` reports `none` for a claude.ai plan login, so take the plan label from `subscriptionType` or `tokenSource`, whose exact values are undocumented (record them in spike c). `accountInfo()` lives on the `Query` object, not on the warm handle that `startup()` returns, so read it from the dedicated detection query in step 1 or from an agent session, never from the fast lane handle. The detection query sends no prompt and spends no tokens; never run `auth status` for this (step 1).

**A fourth way to connect, approved for testing (founder, 7 Oct 2026).** The founder approved testing it in M0 spike (c); whether to offer it is decided in M1. `<claudeBinPath> auth login --console` signs the user in to their Anthropic Console account in the browser, billed by API usage to their Console org; Claude Code stores the credential itself, so no key ever passes through Companion ([CLI reference](https://code.claude.com/docs/en/cli-reference); [Authentication](https://code.claude.com/docs/en/authentication)). Since Claude Code 2.1.242 such a sign in can store a keyless "Anthropic profile" in `~/.config/anthropic`, outside `CLAUDE_CONFIG_DIR`, and since 2.1.286 `auth status` reports a Console sign in's stored key as `api_key`; which `authMethod` a keyless profile reports is undocumented (section 20). The trade off: the fast lane cannot use the direct Messages API on this route, so it always goes through the subprocess. It would open Terminal the same way as step 2. Decision 3 stays as written until the founder decides in M1 whether to offer this route.

Never ask users to paste a `claude setup-token` value: that is collecting a session token. Bedrock, Vertex (Agent Platform) and Foundry work through `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX` and `CLAUDE_CODE_USE_FOUNDRY` for engineers who have them ([Quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart)). Respect branding rules too: "Powered by Claude" is allowed, while naming or styling the product as Claude Code is not ([Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)). Since August 2026 the legal page also allows a plain text statement that Companion runs Anthropic's Claude Code, but never "Claude Code" in a feature name, a UI label or the logo, or wording that suggests a partnership ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)).

One tension must be confirmed in writing, and the legal page itself is part of it. Its "Authentication and credential use" section says developers building products, including with the Agent SDK, should use API key authentication through Claude Console or a supported cloud provider, and that Anthropic does not permit third party developers to offer Claude.ai login in their own apps or to route requests "through Free, Pro, or Max plan credentials on behalf of their users"; Anthropic may enforce this without prior notice ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance), checked 7 Oct 2026). The SDK overview still says "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK" ([Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)). The legal page's carve out covers the user signing in to the unmodified binary, which is what step 2 does, but it does not say a third party may then run its own SDK sessions on that login, and the routing clause is the wording most likely to cover exactly that. Running Claude Code in a product also requires agreeing to Anthropic's Commercial Terms, for example through Companion's own Claude Console organization ([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)).

The history matters. Secondary reports describe 2026 enforcement against tools that routed subscriptions ([Gigazine, 20 Feb 2026](https://gigazine.net/gsc_news/en/20260220-anthropic-third-party-block)), when the legal page said OAuth tokens from Free, Pro or Max accounts may not be used in any other product, tool or service, including the Agent SDK. That wording was removed in early April 2026 (Wayback snapshots, 1 to 13 Apr), so do not cite it as current. Anthropic's support article "Use the Claude Agent SDK with your Claude plan" describes third party apps that authenticate with a user's plan through the Agent SDK as currently drawing from plan limits; a move to a separate monthly credit was paused on 15 June 2026, and Anthropic says it will give notice before any change ([Anthropic support](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)). The carve out and the section on offering Claude Code in products were added only in late August 2026.

So ship the plan option behind a remotely switchable flag, switched off until a written yes, and keep the API key path fully polished so the product survives either reading; because enforcement can come without notice, keep the switch even after a yes. The same question covers Companion's non coding features (Prompt help, Show me how, recaps, Where was I, which runs automatically when the user returns, and the optional check question after a task), which would also run on the user's plan; ask about them explicitly (section 20, item 1). Anthropic publishes no email for this. The official route is contact sales (the legal page's own pointer, which leads to a buying agent chat that can escalate) plus a written ticket through Claude Console support, keeping every reply; a bot reply is not approval, so ask a named Anthropic employee to confirm in writing. A separate risk on the plan route: open user reports describe OAuth refresh races when several Claude Code processes share one plan login, which blank the Keychain login and force a fresh sign in every 1 to 3 days for heavy users (bug [#88583](https://github.com/anthropics/claude-code/issues/88583), secondhand). Companion runs several processes on one login (agent sessions, the warm fast lane, the vision session), so **[verify]** in spike (c) by logging how often a fresh sign in is needed over the following week.

### The provider abstraction

Keep safety, checkpoints, proof, receipts and approvals in the runner core, and make engines thin adapters that emit the normalized events above:

```ts
interface Engine {
  id: "claude-agent-sdk" | "messages-loop" | "codex-app-server";
  detectAuth(): Promise<AuthState>;
  start(spec: AgentSpec, hooks: CoreHooks): AgentHandle;   // CoreHooks = safety + ledger + approvals
}
interface AgentHandle {
  send(text: string): void; interrupt(): Promise<void>; close(): Promise<void>;
  events: AsyncIterable<CompanionEvent>;
}
```

A Companion owned loop on the Messages API is the only route to managed credits, because the no intermediation rule attaches to running Claude Code; confirm with Anthropic sales before building billing. In that loop Companion implements the tools itself, so `CoreHooks` wrap every tool directly. A Codex engine should use `codex app-server` (JSON-RPC 2.0 with `thread/start`, `turn/start`, `turn/interrupt`, streamed `item/*` notifications) rather than the thinner SDK ([Codex app server](https://learn.chatgpt.com/docs/app-server)); note that Codex requires a git working directory unless `skipGitRepoCheck` is set ([Codex SDK README](https://github.com/openai/codex/blob/main/sdk/typescript/README.md)).

### Streaming, interrupt, resume

Run one streaming input `query()` per agent card and feed it from an async queue, so the user can add "also make it blue" mid run. `interrupt()` is the Stop button; the `abortController` is the hard kill on app quit. Persist `session_id` per card and use `resume` after an app restart. `prewarm()` exists but is alpha and freezes `mcpServers`, hooks, `canUseTool`, `settingSources`, `systemPrompt` and plugins for the life of a spare process, so use it only after the options stabilize ([TS reference](https://code.claude.com/docs/en/agent-sdk/typescript)). Map every `SDKAssistantMessage.error` value to a plain sentence on the card. SDK 0.3.291 defines 13: `authentication_failed`, `oauth_org_not_allowed`, `account_on_hold`, `verification_required`, `billing_error`, `rate_limit`, `overloaded`, `invalid_request`, `model_not_found`, `server_error`, `max_output_tokens`, `cloud_credential_error` and `unknown`; add a generic fallback for any new value. `rate_limit` is a 429 (the user's quota) and `overloaded` a 529 (server busy); plan users also get an `SDKRateLimitEvent` whose `errorCode` `credits_required` means the plan's included usage is used up.

### Permission modes

Use `acceptEdits` for the normal path on macOS with the sandbox on, so file edits flow and sandboxed Bash runs without prompts (`autoAllowBashIfSandboxed` defaults to true). Use `plan` for Drive mode's planning phase: plan mode keeps its blocks in SDK sessions and routes writes to `canUseTool` ([SDK permissions](https://code.claude.com/docs/en/agent-sdk/permissions)). Treat `auto` as an experiment: a classifier reviews actions, it needs Opus 4.6+, Sonnet 4.6+ or Fable on the Anthropic API (never Haiku), Anthropic can turn it off server side, its classifier calls are excluded from `total_cost_usd`, and the docs say it "does not guarantee safety" ([Permission modes](https://code.claude.com/docs/en/permission-modes); [TS reference](https://code.claude.com/docs/en/agent-sdk/typescript)). Never use `bypassPermissions` for non engineers.

### Cost, budgets and models

`maxBudgetUsd` stops a query when the client side estimate reaches the cap, with result `subtype: "error_max_budget_usd"` and `terminal_reason: "budget_exhausted"`; `maxTurns` is the second fuse ([TS reference](https://code.claude.com/docs/en/agent-sdk/typescript)). The estimate is computed locally from a bundled price table, may be zero after a crash, and Anthropic says "Do not bill end users or trigger financial decisions from these fields" ([Cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking)). Within one streaming `query()` call, `total_cost_usd` and `modelUsage` are a running total, so store the latest result, adding the last value before each `/clear` (which resets it). Across independent calls with no resume, such as fast lane jobs, each result covers only its own call, so sum them; never sum across resumed calls, which already carry earlier spend ([Cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking)). ### The fast lane: small text jobs that must feel instant

Prompt help, Where was I, recaps, Explain bullets, commitment extraction and intent labelling are short text transformations. Running them through a full agent session would be slow and would bloat context. Use a separate lane:

* **Warm process.** The SDK documents `startup()`, which "pre-warms the CLI subprocess by spawning it and completing the initialize handshake before a prompt is available", and a warm handle's `query()` "can only be called once" ([TS reference](https://code.claude.com/docs/en/agent-sdk/typescript)). Keep exactly one warm handle ready; when a fast job arrives, use it and immediately start the next in the background. `startup()` fixes every option when the handle is created, system prompt included, and the handle's `query()` takes only the prompt, so one handle serves every job only if all jobs share one option set: use one generic fast lane system prompt and send each job's rubric and context block (`profile.md`, `project.md`) inside the user message. `prewarm()` (alpha) documents that a spare holds roughly 230 to 260 MB, so create the spare only after first use in a session or while a likely target app is frontmost.
* **Options** (each documented; the combination is a design choice): `model: "haiku"` (Haiku 4.5, labelled fastest; read the resolved model ID from `system/init` and log it), `tools: []` plus `disallowedTools: ["*"]` (the `"*"` deny is the documented way to remove every tool definition, MCP tools included) plus `strictMcpConfig: true` (required) so claude.ai connectors never load on the plan route, then check that `system/init` lists zero tools; a short custom `systemPrompt` string (not the Claude Code preset), `settingSources: []`, `maxTurns: 1`, `thinking: { type: "disabled" }` and no `effort` (Haiku 4.5 does not support the effort parameter), `includePartialMessages: true` to stream into the card, and `persistSession: false` so prompts are not written to session files ([SDK permissions](https://code.claude.com/docs/en/agent-sdk/permissions); [Models](https://platform.claude.com/docs/en/about-claude/models/overview)).
* **Never let a prompt start with "/".** The SDK runs slash commands from prompt text, and built in commands such as `/clear` and `/compact` work in SDK sessions, so a rough prompt that starts with "/" could run a command instead of being rewritten ([Slash commands](https://code.claude.com/docs/en/agent-sdk/slash-commands)). Put the job's rubric first in the user message so the user's text never opens the prompt.
* **Not `--bare`.** Bare mode starts faster but "never reads OAuth credentials or the system keychain", so it cannot serve subscription users ([Headless](https://code.claude.com/docs/en/headless)). The same page says bare mode "will become the default for `-p` in a future release", so keep the exact pin and test plan auth again on every upgrade.
* **API key users can skip the subprocess.** With the user's own key, a direct streaming Messages API call from the runner appears allowed (their key, billed to them), to be confirmed in the written question to Anthropic (section 20, item 1). It is the fastest path. Note that Haiku 4.5 caches only prompts of 4,096 tokens or more, so a short system prompt will not be cached ([Prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)).
* **Budget.** No official startup numbers exist; historical issue reports show multi second first queries on cold starts (secondhand). Target: the Prompt help card starts streaming within about one second of the hotkey on a warm process. Measure in M0 on both auth routes. Every fast lane job is an independent call, so sum the per job cost estimates in the ledger (see Cost, budgets and models).

### The vision lane: Show me how

Images reach Claude only in streaming input mode: "Single message input mode does **not** support: Direct image attachments in messages" ([Streaming vs single mode](https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode)). Run one dedicated session per walkthrough:

* `prompt` is an `AsyncGenerator<SDKUserMessage>` yielding a user message whose content is the image block first, then a text block with the question and the image's exact pixel size. Validate the image before yielding; an invalid image becomes a text note rather than an error.
* `tools: []` removes every built in tool. Register an in process MCP server with `createSdkMcpServer()` exposing `point_at({x, y, bbox?, targetText, elementKind, ocrId?, confidence, caption})`, `zoom({x, y, w, h})` and `finish()`, allowed by exact name and marked to always load so there is no tool search round trip ([Custom tools](https://code.claude.com/docs/en/agent-sdk/custom-tools)). Structured tool input replaces Clicky's text tags. Add `strictMcpConfig: true` (required) so claude.ai connectors never load next to these tools on the plan route (the in process server is passed through `mcpServers`, so it stays), then check that `system/init` lists only `point_at`, `zoom` and `finish`.
* `persistSession: false` and `settingSources: []`. `persistSession` defaults to true, and the session transcript under `~/.claude/projects` would then hold the base64 screenshot ([TS reference](https://code.claude.com/docs/en/agent-sdk/typescript)).
* `model: "claude-sonnet-5-5"` by default with thinking off or low (Sonnet 5.5's adaptive thinking defaults to high effort, so set `effort: "low"`; on Opus 5.5 thinking is always on); route hard multi step questions to Opus 5.5 after the internal eval. Haiku 4.5 is in the standard image tier and only on the deprecated computer use tool version ([Computer use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)), so use it only as a cheap "is this step done?" check.
* Pre resize every image yourself so neither Claude Code nor the API resizes it. The API accepts up to 2576 px on the long edge and 4,784 visual tokens on Opus 5.5 and Sonnet 5.5 (high resolution tier); Haiku 4.5 is limited to 1568 px and 1,568 tokens (standard tier). Visual tokens are `ceil(w/28) x ceil(h/28)`, so a 1280 x 800 image is about 1,334 tokens (about $0.0027 on Sonnet 5.5). Claude Code caps user images lower: a read only inspection of the Claude Code 2.1.288 binary (minified code, so the reading could be off) found a 2000 x 2000 px limit for Sonnet 5.5 and Opus 5.5, with larger images scaled down, images above about 3.75 MB raw recompressed, and a text note added giving the original and displayed sizes; community issues describe the same 2000 px pipeline for pasted images ([#34566](https://github.com/anthropics/claude-code/issues/34566); [#47063](https://github.com/anthropics/claude-code/issues/47063)). So resize to at most 2000 px on the long edge (default about 1280 px), keep the file well under that byte budget, treat Claude Code's "original ..., displayed at ..." note as an error in development, echo the dimensions back in `point_at`, and check again after every SDK upgrade. The cap is still an open item: it was read from the 2.1.288 binary, and spike (e) confirms it on 2.1.291; the build rule (at most 2000 px, about 1280 px by default) holds either way. Anthropic says to request absolute pixel coordinates, to scale by the resized size and not the padded size, and that overlooking a resize forced by the visual token limit (even when both sides are under the edge limit) is "the most common cause of misaligned coordinates" ([Vision](https://platform.claude.com/docs/en/build-with-claude/vision); [Vision coordinates](https://platform.claude.com/docs/en/build-with-claude/vision-coordinates)). On a direct Messages API call (API key users), mark each screenshot with `transformations: { oversized_image: "error" }` so a resize becomes an error instead; the inspected Claude Code binary shows no sign of passing that field through.
* **[verify] Claude Code may write the screenshot to disk.** The same inspection suggests Claude Code also saves input images in an image store at `<temp root>/<project>/<session>/images/<n>.<ext>`, readable only by the user, where the temp root is `/tmp/claude-<uid>` or `CLAUDE_CODE_TMPDIR`. If that reading is right, `persistSession: false` does not stop it; only a diskless launch mode skips it, and the SDK 0.3.291 types do not expose that mode. This is high impact, because it could break the promise that screen captures never touch disk. Spike (e) settles it by watching those folders during a real run. If it is confirmed, what to do is a founder decision still pending. Only two options keep the rule that captures of the user's screen are never written to disk: (i) API key users' Show me how calls go straight to the Messages API, so images never pass through Claude Code (their key, billed to them); (ii) a supported no disk mode from Anthropic. Pointing `CLAUDE_CODE_TMPDIR` at a Companion owned folder and wiping it after each answer still writes the screen to disk for seconds, so it changes the promise exactly as rewording it would, and needs the founder's explicit yes. For plan users, without an Anthropic switch, Show me how works only with an API key, or the promise changes.
* Keep walkthrough history short (text summaries of earlier steps, not earlier screenshots) or each step resends every previous image.

Claude Code's own computer use MCP works only in interactive sessions with a claude.ai login, not with `-p` ([Computer use](https://code.claude.com/docs/en/computer-use)), so Companion does its own capture and mapping.

## 4. Desktop shell: a panel that never takes focus it was not given

### Panel recipe for macOS

**Updated 7 Oct 2026 (spikes a, a2, a3; founder approved; T01).** On macOS 27, a window converted into a panel after it was created (what tauri-nspanel does: `to_panel` then `add_style_mask`) brings the whole app to the front on any mouse click, even when the panel can never become key. A panel created with `NSWindowStyleMaskNonactivatingPanel` in its initializer does not, with or without a web view inside. So the recipe is now:

1. Build each Tauri webview window hidden and unfocused (`visible(false)`, `focused(false)`, `decorations(false)`, `accept_first_mouse(true)`), and never show it.
2. Create our own `NSPanel` with `initWithContentRect:styleMask:backing:defer:`, passing the non activating flag at creation. The docked character: `Borderless | NonactivatingPanel` (borderless panels never become key, so a click can't take typing). The card: `Titled | NonactivatingPanel | FullSizeContentView` with a transparent, hidden title bar and hidden buttons (titled panels can become key, needed for typing). Set `releasedWhenClosed(false)`, `floatingPanel(true)`, `hidesOnDeactivate(false)`, level 3 and the collection behaviour below.
3. Move the Tauri window's content view (the web view) into the panel with `setContentView`, and give the Tauri window an empty view. IPC, events and the page keep working.
4. Show with `orderFrontRegardless`. The card takes typing with `makeKeyWindow` (on the hotkey, or when clicked) and gives it back with `orderOut` on Esc.
5. Steps 2 (window settings), 4 (level and collection behaviour), 6 (never `window.show()` or `set_focus()`) and 7 (Accessory policy) of the earlier recipe below still apply. Steps 1, 3 and 5 (tauri-nspanel's class macro, `to_panel`, `panel.show()`) are superseded. Tauri's own `set_position` and `set_size` act on the hidden Tauri window, so position our panel with `setFrame:display:` instead.

Proven in spike (a3), macOS 27.0.1: 25 clicks on the character, the hotkey, type and Esc route, and two clicks inside the card (each seen both by the page and by a native mouse monitor) all left the front app unchanged. **[verify] in M2:** while the card holds the keyboard, `NSApp.isActive` reports true even though the front app never changes; check it has no side effects (menus, focus rings, other apps' behaviour). Also still open: clicking the card when it is visible but not key (after the user switched apps), full screen, Spaces, Stage Manager, Dock and display changes, all re-run on the a3 construction.

The earlier tauri-nspanel recipe, kept for the record:

Pin Tauri 2.12.1 (30 Sept 2026, the current stable patch; do not use the 3.0 alphas). Tauri 2.12.0 (26 Sept 2026) added `Builder::activate_ignoring_other_apps`, but its default is true (the app does activate at launch), so call `.activate_ignoring_other_apps(false)`; it only affects the first activation at launch, and any later `set_focus` still activates the app. 2.8.0 added the `focusable` window attribute, but after conversion the panel class decides key behaviour, so `focusable` matters only for the Windows build ([Tauri releases](https://v2.tauri.app/release/tauri/); [Tauri 2.12.1](https://github.com/tauri-apps/tauri/releases/tag/tauri-v2.12.1)). Convert the window into an `NSPanel` with tauri-nspanel (crate 2.1.0, 19 Sept 2026, `branch = "v2.1"` for Tauri 2) ([tauri-nspanel](https://github.com/ahkohd/tauri-nspanel); [docs.rs](https://docs.rs/tauri-nspanel/latest/tauri_nspanel/); [panel methods](https://github.com/ahkohd/tauri-nspanel/blob/v2.1/docs/panel-methods.md)). The recipe, with the v2.1 API names:

1. Register `.plugin(tauri_nspanel::init())` and define the panel class with the `tauri_panel!` macro: `can_become_key_window: true`, `becomes_key_only_if_needed: true`, `is_floating_panel: true`, `hides_on_deactivate: false`. These are fixed per class at compile time and have no runtime setter, so the key window cannot be switched on and off at runtime; the official `hover_activate` example uses this pattern.
2. Create the window hidden with `decorations: false`, `transparent: true`, `alwaysOnTop: true`, `shadow: false`, `focus: false` and `acceptFirstMouse: true`, so the first click on the panel while it is not key reaches the webview **[verify]** in spike (a), since whether WKWebView asks a non activating panel to become key on a plain click is undocumented. `skipTaskbar` only affects Windows and Linux; on macOS the Dock icon goes away through `ActivationPolicy::Accessory` (or `LSUIElement` in Info.plist, which also avoids a brief Dock icon at launch).
3. Convert with `window.to_panel::<DockPanel>()` (or build with `PanelBuilder`) and fetch it later with `app.get_webview_panel(label)`. Add the non activating flag with `panel.add_style_mask(StyleMask::empty().nonactivating_panel().into())`; prefer `add_style_mask` over `set_style_mask`, which replaces Tauri's own flags.
4. Set the collection behavior with `CollectionBehavior::new().can_join_all_spaces().full_screen_auxiliary().stationary().ignores_cycle()`, plus `canJoinAllApplications` for Stage Manager (below), and set the level to 3 with `panel.set_level`, which matches `NSFloatingWindowLevel` (the crate's `PanelLevel::Floating` maps to 4). Floating may not be high enough over other apps' full screen Spaces (below).
5. Show and hide only with `panel.show()` (it orders the panel front without making it key) and `panel.hide()`. Call `panel.make_key_window()` only when the user clicks into a card's text field and `panel.resign_key_window()` when typing ends.
6. Never call Tauri's `window.show()`, `set_focus()`, `maximize()` or `fullscreen()` on the panel. Tao's show calls `makeKeyAndOrderFront`, which makes the panel key and takes typing away from Terminal, and the tauri-nspanel fullscreen example warns that `maximize()` or `fullscreen()` on a full screen auxiliary panel crashes. Tauri's `set_position` and `set_size` still work, because the panel is the same native window and stays registered with Tauri (Handy moves its panel this way) ([tauri-nspanel source](https://github.com/ahkohd/tauri-nspanel/blob/v2.1/src/lib.rs); [Handy overlay](https://github.com/cjpais/Handy/blob/main/src-tauri/src/overlay.rs)). An earlier practitioner write up claimed geometry had to go through the panel handle ([juejin](https://juejin.cn/post/7585006378533453866)); primary sources point the other way, so check geometry once on macOS 27 in the spike.
7. Run the app with `ActivationPolicy::Accessory` so there is no Dock icon and the app never becomes frontmost. On Tauri 2.12.1 or later `macOSPrivateApi` is a no op because the APIs it guarded are always on, so transparency works without it and leaving it true is harmless (on 2.12.0 it is still required, hence the pin); whether this path affects Mac App Store review is unconfirmed and does not matter for direct download. Set `backgroundThrottling: "disabled"` (macOS 14+) so animations and events keep running in a window that is never focused ([Tauri config](https://v2.tauri.app/reference/config/)); the spike still checks this for a visible panel that is never key.

**[verify] A macOS 27 regression to test first.** tauri-nspanel issue 123 (opened 15 Sept 2026, still open) reports that on macOS 27, clicking a panel built with `can_become_key_window: true` and made key on hover activates the app (its menu appears and focus leaves the browser), while the same code worked on macOS 15. The maintainer could not reproduce it on 2.1.0 with `add_style_mask`; the reporter says it still happens. The reporter had `acceptFirstMouse: true`, the same setting step 2 recommends, so spike (a) tests the recipe with it on and off. This hits the "key only while typing" step directly ([tauri-nspanel#123](https://github.com/ahkohd/tauri-nspanel/issues/123)). **Reproduced in spike (a), 7 Oct 2026, macOS 27.0.1 (26A434), tauri-nspanel 2.1.0, Tauri 2.12.1, `acceptFirstMouse: true`:** 4 of 4 real clicks on a panel of this class (on the character, not only the text box) made it key within 3 to 8 ms of the mouse down, before any request, with the app already active, and Panel Spike then became the front app. **Resolved 7 Oct 2026:** design B (a dock that can never become key, typing in a separate card) also failed: clicks on it still brought the app to the front. Spike (a2) showed a natively created non activating panel stays quiet with or without a web view, and spike (a3) proved Tauri's web page inside such a panel stays quiet too; the new recipe is at the top of this section. So the "key only while typing" recipe in this section fails on macOS 27 as written. The plan B (a dock that can never become key, typing in a separate card) and the `acceptFirstMouse: false` variant are under test; see `spikes/a-panel/RESULTS.md`. Two more spike findings: wry 0.57 calls `NSApplication::activate()` every time it builds a webview (`wkwebview/mod.rs`), which `activate_ignoring_other_apps(false)` does not cover; on macOS 27 the request was not granted in 6 launches (the app stayed inactive), and the spike logs it. And Wispr Flow keeps an invisible, click through overlay at window level 1000 over the right 490 points of the screen, so other always on top tools can sit above our edge.

### Click through and transparency

Tauri's ignore cursor events is all or nothing per window. The requests for per pixel click through are closed (tauri#13070 as a duplicate, and tauri#11461, a Windows report of it failing on transparent windows, as not planned), so it will not be implemented; the related request for a forward option, tauri#6164, is still open ([tauri#13070](https://github.com/tauri-apps/tauri/issues/13070); [tauri#11461](https://github.com/tauri-apps/tauri/issues/11461)). For v1, avoid the problem: size the window tightly to the docked character and resize it when a card expands, as the prototype's `set_mode` already does. If a larger transparent canvas becomes necessary, poll the cursor in Rust at 30 to 60 Hz and toggle ignore based on hit rectangles that React reports over IPC. Keep the transparent area small for power as well: a transparent macOS webview was measured at about 620 mW of GPU against 75 mW opaque ([tauri#15471](https://github.com/tauri-apps/tauri/issues/15471)).

### Multi monitor, full screen, Stage Manager

Store position as (display UUID, edge, vertical offset percent), not pixels, and redock on screen parameter changes and scale factor changes. The prototype centers on `monitor.size()`; use the work area instead (`Monitor::work_area()` in Rust, `monitor.workArea` in JS, built from `NSScreen.visibleFrame`; Tauri 2.11 or later fixes its macOS position) so the dock never sits under the menu bar or the Dock ([Tauri Monitor](https://docs.rs/tauri/latest/tauri/window/struct.Monitor.html)). Over full screen apps, `fullScreenAuxiliary` plus `canJoinAllSpaces` on a non activating Accessory panel is the notch app pattern; by default the dock hides while a full screen app is in front (except a brief "needs you" badge), and a setting can keep it visible; the Show me how pointer overlay always appears over full screen apps during a walkthrough the user started. **[verify]** the level: an Apple DTS answer (May 2026, macOS 26) says floating and status bar levels both sit below full screen content and recommends screen saver level, while tauri-nspanel's fullscreen example uses floating and Handy ships at status level; spike (a) tests floating, status and screen saver levels on macOS 27 and keeps the lowest that works, since screen saver level would also draw over other apps' menus ([Apple forums 826308](https://origin-devforums.apple.com/forums/thread/826308)). For Stage Manager, Apple documents `canJoinAllApplications` (macOS 13+) for floating windows and system overlays: such windows stay out of Stage Manager layout and can join other apps' full screen Spaces. Add it through `CollectionBehavior::from_raw` (tauri-nspanel's builder has no method for it), keep it with `canJoinAllSpaces` and `fullScreenAuxiliary`, never with `.primary` or `.auxiliary`, and still test with Stage Manager on and off on macOS 15 and macOS 27 ([canJoinAllApplications](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/canjoinallapplications)).

### Presentation mode is detection plus a hotkey, not capture exclusion

Do not rely on `sharingType = .none`. Electron's docs say ScreenCaptureKit based apps "will capture your window despite `win.setContentProtection(true)`", Apple DTS called inconsistent omission a likely bug (FB21115847), and Zoom shows such windows flickering ([Electron](https://www.electronjs.org/docs/latest/api/browser-window); [Apple forums 808016](https://developer.apple.com/forums/thread/808016); [Zoom community](https://community.zoom.com/meetings-2/flickering-window-in-the-screen-capture-of-zoom-mac-desktop-client-when-nswindowsharingnone-is-set-35876)). Still set content protection as a best effort, but build presentation mode as behavior: the character shrinks to a neutral dot, cards hide their contents, approvals route to the phone. Enter it from a global hotkey, the tray, or heuristics (all **[verify]**): microphone in use via CoreAudio `kAudioDevicePropertyDeviceIsRunningSomewhere`, camera in use via CoreMediaIO, a conferencing app (Zoom, Teams, Meet in a browser, FaceTime) running or frontmost, or a frontmost window covering the whole screen per `CGWindowListCopyWindowInfo` owner PID and bounds: read only `kCGWindowOwnerPID` (mapped to a bundle id with `NSRunningApplication`) and `kCGWindowBounds`, never `kCGWindowOwnerName`, which is nil without Screen Recording on macOS 26 and filled in on 27, undocumented either way, and never titles, which need Screen Recording ([Apple forums 839069](https://developer.apple.com/forums/thread/839069)). Show a one time "I hid myself because you seem to be in a call" with an undo.

### Hotkeys, presence, permissions, login item

Use `tauri-plugin-global-shortcut` with user rebinding. It needs no Accessibility or Input Monitoring permission on macOS, because ordinary shortcuts register through Carbon `RegisterEventHotKey`; avoid media keys, which go through an event tap, and pick defaults that include Cmd or Ctrl ([global-hotkey source](https://github.com/tauri-apps/global-hotkey/blob/dev/src/platform_impl/macos/mod.rs)). Watch the frontmost app through `NSWorkspace` notifications (no permission) to hold non blocking events while a terminal or editor is frontmost and to drive take the wheel (below). No Build mode flow needs Accessibility, Input Monitoring or Screen Recording; Prompt help (Accessibility), Show me how (Screen Recording, plus Accessibility for snapping) and voice (Microphone) request their own permissions the first time they are used (section 17), and nothing ever requests Input Monitoring.

**Stop everything.** A global kill switch hotkey (user rebindable) sends `agent.interruptAll`: every running agent, saved task and walkthrough stops at once, the microphone and any capture end, and the characters show Off until resumed. It works even when the dock is hidden.

**Take the wheel, without reading keystrokes.** While Drive runs on a project, pause the agent within about a second when (a) the user brings that project's editor or terminal to the front (frontmost app plus the editor's window or workspace path where available **[verify]** per editor), or (b) a file in the project changes that the agent did not write (FSEvents on the project folder, compared against the agent's own `PostToolUse` file list and the snapshot diff). Resume on a click or hotkey. This needs no permission and never sees what the user types. Launch at login through `SMAppService.mainApp` (macOS 13+, no permission prompt, listed in Login Items) called from Rust with `objc2-service-management`, or through `tauri-plugin-autostart` in its default LaunchAgent mode; never use its AppleScript mode, which sends commands to System Events and triggers an Automation prompt ([autostart source](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/autostart/src/lib.rs)). Tray via `TrayIconBuilder`.

### Signing, notarization, updates

A Developer ID Application certificate requires the $99 per year Apple Developer Program; set `APPLE_SIGNING_IDENTITY`, notarize with an app specific password, which is the method the M0 spike uses (Tauri reads `APPLE_ID`, `APPLE_PASSWORD` and `APPLE_TEAM_ID`; our own DMG step can use a keychain profile saved once with `xcrun notarytool store-credentials`), and import the certificate in CI with `APPLE_CERTIFICATE`, which works only together with `APPLE_CERTIFICATE_PASSWORD` ([Tauri macOS signing](https://v2.tauri.app/distribute/sign/macos/)). An App Store Connect API key (`APPLE_API_ISSUER`, `APPLE_API_KEY`, `APPLE_API_KEY_PATH`) is an alternative for CI later, but it must be a Team key, because individual API keys cannot use `notarytool` ([App Store Connect API keys](https://developer.apple.com/documentation/appstoreconnectapi/creating-api-keys-for-app-store-connect-api)). Notarize and staple both the app and the DMG. Tauri notarizes and staples only the `.app`; it signs the DMG but never notarizes it, so notarizing and stapling the DMG is a step in our own script (read from the bundler source, [bundler sign.rs](https://github.com/tauri-apps/tauri/blob/tauri-bundler-v2.10.1/crates/tauri-bundler/src/bundle/macos/sign.rs)). Auto update with `tauri-plugin-updater`: generate a minisign key with `tauri signer generate`, back it up offline, and set `TAURI_SIGNING_PRIVATE_KEY` as a real environment variable; "if you lose this key you will NOT be able to publish new updates" ([Tauri updater](https://v2.tauri.app/plugin/updater/)). Host `latest.json` and `.app.tar.gz` artifacts on GitHub Releases. Homebrew comes later through your own tap with a cask pointing at the notarized DMG **[verify]** current homebrew/cask notability rules.

### Windows follow up

Use a borderless transparent top level window with `focusable: false`, skip taskbar and always on top, adding `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` through `windows-rs` if `focusable` alone still activates. Capture exclusion works here: `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` hides the window from captures on Windows 10 2004 and later, though Microsoft calls it "not a security feature" ([Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)). Presentation heuristics use `SHQueryUserNotificationState` **[verify]**. Never create a full monitor topmost window, which makes Windows believe a full screen app is running ([Carnac #12](https://github.com/doggy8088/carnac/issues/12)). Position from the monitor work area and scale factor. The bigger Windows gaps are engine side: the Claude Code sandbox does not run on native Windows ("Claude Code runs commands unsandboxed") and without Git for Windows Claude Code uses a PowerShell tool instead of Bash ([Sandboxing](https://code.claude.com/docs/en/sandboxing); [Setup](https://code.claude.com/docs/en/setup)). So the Windows build needs stricter ask rules routed to approvals, or an optional WSL2 mode.

Signing from India: Azure Artifact Signing public trust is limited to individuals in the USA and Canada and organizations in the USA, Canada, EU and UK ([Microsoft Q&A](https://learn.microsoft.com/en-us/answers/questions/2243504/trusted-signing-for-other-countries)). The options are an OV certificate on a cloud HSM issued to an individual (roughly $100 to $400 a year **[verify]**), a Microsoft Store MSIX listing (free for individuals, no SmartScreen warning; acceptable only as a secondary channel, since direct download is the founder's decision) or a US entity that qualifies for Artifact Signing ([Microsoft Learn code signing options](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options)). EV certificates no longer grant instant SmartScreen reputation ([ToDesktop](https://www.todesktop.com/blog/posts/windows-apps-psa-ev-certs-do-not-grant-immediate-reputation-anymore)).

## 5. Runner packaging: keep Anthropic's signature on Anthropic's binary

Compile the runner with `bun build --compile` once per target, using Bun 1.4.2 or newer: 1.4.2 includes a fix for broken ad hoc signatures that macOS 27 kills at launch ([bun#39837](https://github.com/oven-sh/bun/pull/39837)). Three naming schemes meet here, so the build script needs a lookup table: Bun's `--target` names (`bun-darwin-arm64`, `bun-darwin-x64`, `bun-windows-x64`, `bun-windows-arm64`), the Rust target triples Tauri expects in the output names (`runner-aarch64-apple-darwin`, `runner-x86_64-apple-darwin`, `runner-x86_64-pc-windows-msvc.exe`, `runner-aarch64-pc-windows-msvc.exe`), and the npm suffixes of the SDK's binary packages (`darwin-arm64`, `darwin-x64`, `win32-x64`, `win32-arm64`) ([Bun executables](https://bun.com/docs/bundler/executables)). Register the runner as the only Tauri sidecar via `bundle.externalBin`, named `runner-{target-triple}`; the bundler drops the suffix when it copies the file into `Contents/MacOS` ([Tauri config](https://v2.tauri.app/reference/config/)). Spawn it from Rust, not from the webview, and remove the shell plugin's spawn permission from the UI capability. When bundling the SDK into your own build, import `@anthropic-ai/claude-agent-sdk/core` and never load both entry points in one process ([TS reference](https://code.claude.com/docs/en/agent-sdk/typescript)).

The Claude Code binary is the delicate part. The SDK documents embedding it as a file asset and calling `extractFromBunfs()`, which copies it to a per user temp directory at runtime ([TS reference](https://code.claude.com/docs/en/agent-sdk/typescript)). Prefer shipping it as its own file, copied byte for byte from the matching optional dependency at build time into the bundle through `bundle.macOS.files` (for example `"MacOS/claude": "../vendor/claude"`, or `Helpers/claude`; the copy is staged in `app/vendor/`, which git always ignores, and `binaries/` holds only the runner sidecar), and pass its path in `pathToClaudeCodeExecutable`. Never ship it as an `externalBin`: Tauri 2.12 (tauri-bundler 2.10.1) signs every `externalBin` again with `codesign --force` using the app's identity and entitlements, which replaces Anthropic's signature, and has no setting to skip one binary. Files in `bundle.macOS.files` are copied but never signed, and the outer app is signed without `--deep`, so Anthropic's signature survives (read from the bundler source; no Tauri doc states it) ([bundler app.rs](https://github.com/tauri-apps/tauri/blob/tauri-bundler-v2.10.1/crates/tauri-bundler/src/bundle/macos/app.rs); [bundler sign.rs](https://github.com/tauri-apps/tauri/blob/tauri-bundler-v2.10.1/crates/tauri-bundler/src/bundle/macos/sign.rs)). If a Tauri update ever changes this, build with `tauri build --no-sign` and sign with our own script. Inspection of `@anthropic-ai/claude-agent-sdk-darwin-arm64@0.3.291` for this report (6 Oct 2026, from the npm tarball) found a 233 MB Mach-O binary (102 MB compressed) already signed by **"Developer ID Application: Anthropic PBC (Q6L2SF6YDW)"**, identifier `com.anthropic.claude-code`, with the hardened runtime flag set and entitlements `allow-jit`, `allow-unsigned-executable-memory`, `disable-library-validation`, `device.audio-input` and `automation.apple-events`; the `win32-x64` package unpacks to 253 MB ([npm package](https://registry.npmjs.org/@anthropic-ai/claude-agent-sdk-darwin-arm64)). That has two consequences. Configure the bundle so Tauri does **not** sign this file again (a second signature replaces Anthropic's, which is the most literal reading of "modified"), and have CI check with `codesign` that the bundled file still shows `TeamIdentifier=Q6L2SF6YDW` and that its SHA-256 matches the file in the npm package. And verify in the M0 spike that notarization accepts a nested executable carrying another team's Developer ID signature **[verify]**: Apple's notarization page asks every Mach-O for a Developer ID signature with a secure timestamp and hardened runtime but never says it must belong to the submitting team, and no Apple page covers mixed team nested code directly, so only a real `notarytool` submission settles it ([Apple notarization issues](https://developer.apple.com/documentation/security/resolving-common-notarization-issues)). Entitlements for our own code go in `bundle.macOS.entitlements`, and Tauri passes that one file to every target it signs (the main executable, each `externalBin` and the `.app`), with hardened runtime on by default, so the runner and the main app share one entitlements file and there is no per sidecar set ([bundler sign.rs](https://github.com/tauri-apps/tauri/blob/tauri-bundler-v2.10.1/crates/tauri-bundler/src/bundle/macos/sign.rs)). Start with `allow-jit` and `allow-unsigned-executable-memory`, which Anthropic's own Bun compiled binary runs with, and add Bun's other recommended entitlements only if the runner crashes **[verify]** for your build. The Claude binary keeps its own entitlements because Tauri never signs it. Expect a DMG of roughly 150 to 300 MB; if size hurts conversion, a later option is to have the user install Claude Code with Anthropic's own installer and point `pathToClaudeCodeExecutable` at it, accepting version skew.

Fix `PATH` before anything spawns. Apps launched from Finder get a minimal `PATH`, so `git`, `node` and Homebrew tools vanish; read the login shell's `PATH` once at startup with our own `$SHELL -ilc 'printf %s "$PATH"'` call and a 3 second timeout, and pass it explicitly in the SDK `env`. If the shell is nushell or the call fails, fall back to a fixed list: `/opt/homebrew/bin`, `/usr/local/bin`, `~/.local/bin`, `~/.bun/bin`, `~/.cargo/bin`, plus the system paths. Do not use the `fix-path-env-rs` crate: it is a git only dependency (0.0.0, not on crates.io), has no timeout, and fails under nushell (open issue #14) ([fix-path-env-rs](https://github.com/tauri-apps/fix-path-env-rs)). Fish accepts `-i`, `-l` and `-c` but is untested **[verify]**. A related trap: on a fresh Mac, `/usr/bin/git` is a stub that pops the Command Line Tools installer. Non engineers will hit it on the first checkpoint, so either bundle a git or run an environment doctor at onboarding that installs Command Line Tools and a Node runtime with clear copy. GitHub Desktop's dugite approach bundles the git build from `dugite-native`, which is GPL-2.0 like Git (so the source must be offered alongside) and 41 to 66 MB compressed for macOS, and every Mach-O inside would need our own Developer ID signature before notarization; that favours the environment doctor for the alpha ([dugite-native](https://github.com/desktop/dugite-native)).

## 6. Checkpoints and undo: snapshot the whole tree before every turn

SDK file checkpointing tracks only `Write`, `Edit` and `NotebookEdit`; Bash changes and most subagent edits are invisible to it, rewind is same session only, and directory moves are not undone ([File checkpointing](https://code.claude.com/docs/en/agent-sdk/file-checkpointing)). Keep it enabled as a fast partial layer, but make Companion's own snapshot the source of truth. Codex "ghost commits" (temporary index, `git add --all`, `write-tree`, `commit-tree`, never updating branches), Docker Agent's tree only shadow repo and Roo Code's shadow repo all converge on the same idea ([Codex git tooling](https://forge.lthn.ai/core/core-agent-ide/commit/e0fbc112c772f87c9386cb2de992fbf8cdcb07d7); [Docker Agent snapshots](https://docs.docker.com/ai/docker-agent/features/snapshots.md); [Roo Code](https://roocodeinc.github.io/Roo-Code/features/checkpoints/)).

**Design.** One bare shadow repository per project at `~/Library/Application Support/Companion/shadow/<projectId>.git`. Every git call uses `--git-dir=<shadow> --work-tree=<project>` and `GIT_INDEX_FILE=<tmp>`, so the user's `.git`, index, branches and history are never written, and non git folders work without `git init`. Work tree `.gitignore` files are honored automatically; copy the project's `.git/info/exclude` into the shadow's `info/exclude` and add Companion's own excludes (`node_modules/`, `.next/`, `dist/`, `build/`, `.turbo/`, caches). Snapshot with `add -A`, `write-tree`, then `commit-tree` with the previous checkpoint as parent and store under `refs/cp/<n>`. Take a snapshot when an agent turn starts (the `UserPromptSubmit` point) and again after the turn ends, so every receipt diff is exact. Port the prototype's tests to this layout and add the cases below.

**Restore.** Restore into the work tree from the target tree without touching the user's index: read the target into a temporary index, `checkout-index -a -f`, then delete paths present in the current snapshot but absent from the target (computed from `diff --name-status`). Before any restore, take a fresh snapshot so undo itself is undoable. Companion never writes the user's index or `HEAD`, which fixes the prototype's lost staging. It records the user's `HEAD` at checkpoint time, reading only. If an agent made a commit during the step, the receipt shows the exact git command that would move the branch back (for example `git reset --soft <recordedHead>`) for the user to run themselves, or offers it as an approval card, where it runs as an agent git command like any other (founder decision, 7 Oct 2026, F13).

**Edge cases.** Skip newly added files over 2 MiB, as Docker Agent does, and list them in the receipt. Nested repositories and submodules are stored as gitlinks, so their contents are not snapshotted; Roo disables checkpoints in that case, and Companion should instead warn per nested repo. Symlinks snapshot as links; pnpm's hard linked stores are excluded with `node_modules`. Hash `.env*` files (normally ignored) before and after each step; if one changed, keep a `0600` copy in the shadow metadata directory so undo can restore it, and say so on the receipt. Cap the shadow store (for example 2 GB per project), keep the most recent 100 checkpoints (Claude Code's own per session limit ([Checkpointing](https://code.claude.com/docs/en/checkpointing))) and `gc` weekly. Concurrent agents in one folder share one shadow repo, so serialize snapshot calls with a per project lock, and run agents in one project one at a time by default. A git worktree per agent (Conductor's model ([Conductor](https://www.conductor.build/docs/concepts/git-worktrees))) writes into the user's `.git`, so Companion does not create them (founder decision, 7 Oct 2026, F13).

**Agents and the user's git.** Companion's own machinery never writes the user's repository. Agent commands that would (`git commit`, `checkout`, `switch`, `reset`, `branch`, `stash`, `rebase`, `merge`, `tag`, `push`) are routed to an approval by a `PreToolUse` rule, except a commit the user asked for in that task. Undoing an agent's commit takes the same path: the exact command shown to the user, or an approval card (F13). The research is inconsistent about `git push`: this section routes it to an approval, while section 8 and the section 3 example list `Bash(git push*)` as a deny rule and the M1 hook test was first written as "denied". The M1 plan settles it (the section 18 test now checks only that it never runs without the user), and the recommendation is an approval through the hook's `ask` with no deny rule, because the founder's rule says agent git changes need approval.

**Founder decision, 7 Oct 2026: no undo helper, no per agent worktrees (F13).** Both would have written the user's git, which the rule forbids. When an agent made a commit, Companion shows the exact git command to undo it, or asks through an approval card. The rule stays exactly as written.

**Irreversible actions.** File snapshots cannot undo network side effects. Classify in `PreToolUse` and flag `undoable: false` before running: deploys, `git push`, package publishing, `npm i -g` or `brew install`, remote database commands (`supabase db push`, `psql` against a non local host, `prisma migrate deploy`), `curl` or `fetch` with a mutating method, email or payment API calls from scripts, and any write outside the project. Each requires an approval naming the checkpoint it follows, and the receipt lists it under "not undoable". The Replit incident, where an agent deleted a production database during a code freeze despite instructions, shows that instructions are not controls ([eWeek](https://www.eweek.com/news/replit-ai-coding-assistant-failure/)).

## 7. Proof before done: exit codes first, eyes last

Claude Code Desktop already starts dev servers, screenshots, inspects the DOM and fixes what it finds, storing server config in `.claude/launch.json` with `runtimeExecutable`, `runtimeArgs`, `port`, `cwd`, `env`, `autoPort` and `url`; with `autoPort: true` it picks a free port and passes it as `PORT`, with `false` it fails (for OAuth callback or CORS bound apps), and unset asks once ([Desktop docs](https://code.claude.com/docs/en/desktop)). Cursor's cloud agents attach videos, screenshots and logs as evidence ([Cursor blog](https://cursor.com/blog/agent-computer-use)). Companion should read and write the same `launch.json` format so users who also use Claude Code Desktop share one config.

The proof ladder, run by the runner after the `Stop` hook fires for a turn that changed files:

| Rung | Check | Pass signal | Notes |
|---|---|---|---|
| 1 | Install if lockfile changed | exit 0 | Use the lockfile's manager (pnpm, npm, bun, yarn) |
| 2 | Build, typecheck, lint | exit 0 per script present | Run with `CI=1`, timeout 5 min, keep last 30 lines |
| 3 | Tests | exit 0 and test count not lower than at checkpoint | Fail if the step edited, deleted or skipped tests (diff test files, grep `.skip`/`.only`) |
| 4 | Dev server | port answers within 60 s | `launch.json`, `autoPort`, `PORT`; refuse to attach to a server started before the step (stale build) |
| 5 | Playwright smoke | page loads, no console errors, no failed requests, expected text or selector present, one click through of the changed flow | Wait for network idle; headless bundled Chromium |
| 6 | Vision judgment | model verdict with screenshot | Evidence on the receipt only, never the pass signal |
| 7 | Second model review | A separate, read only review session (Opus 5.5 by default, no edit tools) reads the request and the step's diff, not the author's transcript, and returns approve, comment or send back with a reason | Every step; a short review for small diffs, a full one when the diff touches auth, payments, migrations, env or deploy config. A send back returns to the Builder within the budget |

Proof screenshots are of the app under build in a headless browser, never the user's screen; they are stored with the receipt and are the raw material for the build timelapse, which is assembled from proof screenshots and the timeline, never from a screen recording. Use Playwright's bundled Chromium, downloaded lazily on first proof rather than shipped in the DMG; one team abandoned driving the user's real Chrome because it "silently blocks `--load-extension`" under Playwright ([opengstack design doc](https://cdn.jsdelivr.net/npm/opengstack@0.15.1/docs/designs/CHROME_VS_CHROMIUM_EXPLORATION.md); [Playwright BrowserType](https://Playwright.dev/docs/api/class-browsertype)). On failure, send the evidence back into the same streaming session ("The build failed with ...; fix it") up to two retries within the card's budget, then stop with "not done" and the evidence. A turn is never shown as done while a rung fails or the reviewer sent it back; the character goes to `error`, not `done`. Every user, Free or Plus, gets rungs 1 to 5; Plus adds rungs 6 and 7 (founder decision, 7 Oct 2026, F14). Measure Chromium download size in the spike; it was not found in sources. **Built and measured (16 Oct 2026):** nothing downloads on its own. When a check had to skip the page because the browser is missing, the card offers "Get the browser check (about 200 MB, once)" and only that press starts Playwright's own installer (Playwright's servers, retried, thrown away if bytes are missing; its download host cannot be changed by the person's environment), with progress, one download at a time, ended by Stop everything. Chrome Headless Shell 156 (Playwright 1.64, build 1248) takes 203 MB on disk on an Apple silicon Mac; its archive is 103,778,487 bytes (about 104 MB) over the network. Playwright's installer always adds FFmpeg (about 1 MB, same servers, unused by Companion) after the browser; only the browser's progress is shown. The installer ends with the engine even when the engine is ended by force. See T07.

## 8. Safety: structure beats instructions

Layer the controls so that no single one has to be perfect.

1. **OS sandbox for shell commands (macOS).** Claude Code's sandbox is the open source `@anthropic-ai/sandbox-runtime` (Seatbelt on macOS); network leaves only through a local proxy whose allowlist starts empty; newer credential masking shows commands a sentinel and injects the real secret only for allowed hosts. It covers shell commands only, not file tools, MCP servers or hooks ([Sandboxing](https://code.claude.com/docs/en/sandboxing); [sandbox-runtime](https://github.com/anthropics/sandbox-runtime)). Enable it with `allowUnsandboxedCommands: false` and allow package registries plus the project's declared API hosts. If the sandbox cannot start, the default `failIfUnavailable: true` ends the session with `error_during_execution`; surface that rather than silently running unsandboxed.
2. **Deny rules** in `disallowedTools` for scoped patterns (`Bash(git push*)`, `Bash(sudo *)`, `Bash(rm -rf *)`, publishing and deploy commands). Deny rules hold "even in `bypassPermissions` mode" ([SDK permissions](https://code.claude.com/docs/en/agent-sdk/permissions)). The `Bash(git push*)` entry here (and in the section 3 example) conflicts with section 6, which routes `git push` to an approval; the M1 plan settles it, and the recommendation is an approval through the hook's `ask` with no deny rule, because the founder's rule says agent git changes need approval. Deploys run through the runner's Ship adapters, not agent Bash, so the deploy deny rules do not block Ship.
3. **`PreToolUse` hooks** for anything a pattern cannot express: resolve every path argument and deny writes outside the project, deny edits to `.env*` unless the step is explicitly about secrets, classify irreversible actions, and return `ask` to route to Companion's approval UI. When several hooks disagree, `deny` beats `defer` beats `ask` beats `allow`, and a hook `allow` does not skip deny or ask rules ([Hooks](https://code.claude.com/docs/en/hooks); [SDK hooks](https://code.claude.com/docs/en/agent-sdk/hooks)). Port the prototype's regex list here as one input, not the whole defense.
4. **`canUseTool`** renders approvals for what falls through. Leave `permissionPrompts: 'host'` so unanswered prompts reach the UI.
5. **Pre ship gates.** Run gitleaks (MIT, offline, fast) on the diff and on built client bundles, where `NEXT_PUBLIC_` style keys leak; trufflehog (AGPL, verifies live secrets) is an optional deeper scan ([AppSec Santa](https://appsecsanta.com/secret-scanning-tools/gitleaks-vs-trufflehog)). If Supabase is detected, block shipping when any table exposed to the Data API lacks RLS, using the open source Security Advisor lints or a direct `pg_tables` / `pg_class.relrowsecurity` query ([Supabase hardening](https://supabase.com/blog/hardening-supabase.md)). The evidence for this gate is strong: a Q2 2026 scan of 23,792 AI built apps attributed 96% of critical findings to Supabase RLS misconfiguration ([securityscanner.dev](https://securityscanner.dev/reports/2026-q2)), and CVE-2025-48757 covered 170 of 1,645 Lovable apps exposing data through missing RLS ([SentinelOne](https://www.sentinelone.com/vulnerability-database/cve-2025-48757/)).
6. **Project trust.** Because `settingSources: ["project"]` loads the project's `.claude/settings.json` and its hooks, a downloaded project can run commands on session start. On first open of a folder, list any project hooks and MCP servers and ask before loading them (inference from the settings docs; **[verify]** whether the SDK applies Claude Code's workspace trust check).
7. **Production separation.** Never give the agent production database credentials; when a `.env` holds a production URL, mask it through the sandbox's credential injection and require approval for any command that targets it.

On Windows layers 1 and 6 weaken, so move more Bash patterns into ask rules there and offer WSL2 for engineers.

## 10. Remote approvals: a dumb relay, a smart phone

Anthropic's own phone surfaces do not fit: Remote Control requires Pro, Max, Team or Enterprise and does not accept API keys, and Dispatch requires Pro or Max ([Remote Control](https://code.claude.com/docs/en/remote-control); [Desktop docs](https://code.claude.com/docs/en/desktop)). Build Companion's own, in the shape Happy uses ("Your code never leaves your devices unencrypted") ([Happy](https://github.com/slopus/happy)).

**Pairing.** The desktop shows a QR code containing a one time pairing token, the relay URL and the desktop's X25519 public key. The PWA generates its own key pair, stores the private key in IndexedDB as a non extractable WebCrypto key **[verify]** X25519 support in iOS Safari (fall back to libsodium WASM), and registers its public key through the relay. Both sides then derive a shared key; libsodium `crypto_box` style sealing is the simplest correct choice.

**Relay.** A Cloudflare Worker with one Durable Object per pairing stores ciphertext envelopes, push subscriptions and a monotonic counter, and holds WebSocket connections to the desktop. It never sees plaintext. Push payloads carry no content ("Companion needs you"); the PWA fetches and decrypts on open.

**Binding.** Every approval request carries `approvalId`, `checkpointId`, `toolUseId`, a hash of the exact tool input, a nonce and `expiresAt`. The phone signs its decision over all of these; the runner verifies the signature, the nonce and the expiry, and applies it only if that tool call is still pending. A decision can never approve a different command or replay later.

**Long waits.** When the user is away, return `defer` from `PreToolUse`: the turn ends gracefully with `stop_reason: "tool_deferred"` and `deferred_tool_use` describing the call, and the session resumes with the same `session_id` once an answer arrives ([TS reference](https://code.claude.com/docs/en/agent-sdk/typescript); [Hooks](https://code.claude.com/docs/en/hooks)). That frees the process instead of holding a hook open for an hour.

**iOS PWA requirements.** Web Push works on iOS and iPadOS 16.4 and later only for a site added to the Home Screen, with a manifest `display` of `standalone` or `fullscreen`, a permission request triggered by a direct tap, and no Apple Developer membership needed; allow `*.push.apple.com` ([WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)). The Add to Home Screen step is the main friction for non engineers, so the onboarding card must walk through it with screenshots. Whether iOS 26 changed requirements (Declarative Web Push) was not verified.

**Telegram.** A bot is free, uses inline keyboard buttons that send `callback_query` updates, and runs on long polling or a webhook ([Telegram Bots FAQ](https://core.telegram.org/bots/faq)). Bot chats are not end to end encrypted, so send summaries only, never code, diffs or secrets, and allow Telegram to approve only low risk categories; production deploys and anything marked irreversible require the signed PWA path. WhatsApp stays out: assistant style bots are banned from 15 Jan 2026 ([respond.io](https://respond.io/blog/whatsapp-general-purpose-chatbots-ban)).

## 11. Memory, Explain and Where was I: plain files, a local log, no watching

### Memory files

Use the cross vendor convention. `AGENTS.md` is a founding project of the Linux Foundation's Agentic AI Foundation and is read by Codex, Cursor, Copilot and others ([AAIF](https://aaif.io/news/linux-foundation-announces-formation-of-aaif)). Claude Code reads `AGENTS.md` only when no `CLAUDE.md` exists, unless `CLAUDE.md` imports it ([Memory](https://code.claude.com/docs/en/memory)). So Companion writes:

| File | Owner | Content |
|---|---|---|
| `AGENTS.md` | Project, shared by all agents | How to run, build and test; stack; conventions; things never to touch |
| `CLAUDE.md` | Project | First line `@AGENTS.md`, then only Claude specific notes |
| `.claude/launch.json` | Project | Dev server config shared with Claude Code Desktop |
| `.companion/project.md` | Companion | Goals, decisions, house rules, what "done" means, deploy targets |
| `~/Library/Application Support/Companion/profile.md` | User | How this person works: questionnaire answers, tone and length, explanation level, risk tolerance, preferred stack, things learned |
| `.companion/session.md` | Companion, expires | Volatile notes for the current Drive run; cleared when the run ends |

Inject `profile.md` and `project.md` through `systemPrompt.append` for agent sessions and as a short context block for fast lane jobs, and disable Claude Code's auto memory with `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` so nothing is remembered where the user cannot see it ([Claude Code features](https://code.claude.com/docs/en/agent-sdk/claude-code-features)). Ask before creating `AGENTS.md` in a project that already has a team convention.

**What may be learned.** Two kinds. Project memory may be derived from the granted project folder and agent runs (stack, scripts, decisions, Researcher notes), always written visibly with its source. The profile learns only from explicit signals inside Companion: questionnaire answers, approvals and rejections, undo clicks, edits the user makes to agent output, stated corrections ("shorter", "never touch auth"). Never anything from the screen, other apps' text, voice audio, or connected sources beyond the specific Loop Closer items the user saw. Never health, money, relationships or moods, even if mentioned: memory of personal matters is one of the tests in New York's AI companion law ([MoFo](https://www.mofo.com/resources/insights/251120-new-york-and-california-enact-landmark-ai)). Never secrets or `.env` values.

**The "What I know about you" page.** Every memory line carries provenance (source, date, and the quote or event that created it), with Edit and Forget per line, Pause (keep but learn nothing new), Erase all (with confirmation), and an "off the record" switch for a single task that neither reads nor writes memory. Each new line triggers a toast with Undo for ten seconds (`memory.saved` event). This mirrors how the Claude app and ChatGPT present memory ([Claude memory](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context); [ChatGPT memory](https://help.openai.com/en/articles/8590148-memory-faq)). Export as a readable file. Cap `profile.md` near 200 lines, following Claude Code's own index cap.

### The task log

A local SQLite database in the runner (`bun:sqlite`) holds: tasks (request text, agent, project, start and end, outcome, cost estimate), timeline events (the protocol events, minus content the user marked off the record), decisions and their answers, house rules, approvals, Loop Closer items with their evidence and status, Pattern Catcher candidates, and saved tasks. It is the source for receipts, the timeline UI, Where was I, recaps, stalled project detection and Pattern Catcher. Keep it in Application Support, never sync it in v1, and give the privacy page a "delete all" that removes it.

### Explain

Ship a custom output style file with the app, built from Claude Code's Explanatory style, and select it for Curious agent sessions when Explain is on. Output styles work in Agent SDK sessions and are markdown with frontmatter ([Output styles](https://code.claude.com/docs/en/output-styles)). Render the explanation as two or three "why" bullets in a collapsible section under the result card, not interleaved in the step stream, plus at most one optional multiple choice check question generated by the fast lane. Explanations cost extra output tokens; label it.

### Where was I and recaps

Generate lazily on return, never continuously. Trigger when the shell sees the user return (screen unlock, or first interaction after N minutes, default 30) and the task log shows something ran or finished while they were away. The fast lane receives only task log rows (requests, outcomes, pending approvals) and returns at most three lines, mirroring Claude Code's 400 character recap ([Claude Code week 17](https://code.claude.com/docs/en/whats-new/2026-w17.md)). The card is labelled AI written and says "From your tasks with Companion only". Weekly and end of session recaps (v1.1) are the same pipeline over a longer window.

## 12. Characters: one Rive file per species, one state input

Rive fits abstract, stateful, skinnable characters: state machines plus data binding, a web runtime where `canvas-lite` is 222 KB brotli against 567 KB for `canvas` and 648 KB for `webgl2`, and Duolingo running its characters on it at scale ([Rive runtime sizes](https://rive.app/docs/runtimes/runtime-sizes.md); [Duolingo](https://blog.duolingo.com/world-character-visemes)). Model each species as one `.riv` file with one state machine, an enum or number input `state` matching the protocol's agent states plus the shell's `seeingScreen` and `readingText`, a number input `intensity` for personality, and a boolean `prefersReducedMotion`. Make skins data bound view model instances (colors, materials), not separate files. Rive "does not automatically apply reduced motion", so read `prefers-reduced-motion` in React and drive the bound boolean, swapping movement for opacity and color changes ([Rive reduced motion](https://rive.app/docs/editor/accessibility/reduced-motion.md)).

Licensing: the free editor plan exports but forces a Rive splash screen; Cadet at $9 per seat per month removes it ([Rive pricing](https://rive.app/pricing), checked 6 Oct 2026). The Flutter runtime is MIT ([pub.dev](https://pub.dev/packages/rive/license)), and so is the web runtime: `@rive-app/canvas`, `canvas-lite`, `webgl2` and the React packages are MIT on npm, checked 7 Oct 2026 ([npm](https://www.npmjs.com/package/@rive-app/canvas); [rive-wasm license](https://github.com/rive-app/rive-wasm/blob/master/LICENSE)). Keep its notice in the app's acknowledgements.

Idle budget: the docked character is on screen all day, so set targets and measure them on an M1 Air in M2: under 1% average CPU and no measurable GPU wake in idle after 10 seconds. Achieve it by pausing the state machine (or rendering a static frame) after N seconds idle, when the panel is occluded, in presentation mode and on low battery; capping idle animation at 30 fps or less; keeping the canvas the size of the character, not the window; and avoiding backdrop blur. Size targets for design: docked tab about 48 to 56 pt with the character drawn inside it (readable at 32 pt), expanded agent card about 360 by 560 pt (the prototype's 68 pt tab and 380 by 620 pt panel are a good start).

## 13. Prompt help: read the field, paste the answer, never type into the panel

### Read

On the hotkey, Rust records the frontmost app's process id and bundle id, then reads text in this order:

1. **Accessibility first.** `AXUIElementCreateSystemWide()`, then `kAXFocusedUIElementAttribute`, then `kAXSelectedTextAttribute` (a selection wins) or `kAXValueAttribute` (the whole field). This touches no clipboard. Write our own reader on `objc2-application-services` that reads the selection or the whole value. The `get-selected-text` crate (0.1.6, May 2024, dormant) is a reference only: it reads just `kAXSelectedTextAttribute`, never the whole value, and its fallback runs an AppleScript Cmd+C through System Events, which adds an Automation prompt and restores only plain text ([get-selected-text](https://github.com/yetone/get-selected-text)). PopClip's developer describes the same approach with a clipboard fallback for apps that expose nothing (vendor forum).
2. **Electron and Chromium apps** build their accessibility tree lazily. In Electron apps (Claude desktop on Electron 44, Cursor on Electron 37, VS Code, Slack), reading the app element's `AXRole` turns on basic accessibility, web content included, at once; setting `AXManualAccessibility` turns on the full tree only after a built in delay of about 2 seconds, and is ignored while VoiceOver is on ([Electron accessibility](https://www.electronjs.org/docs/latest/tutorial/accessibility); [Electron source](https://github.com/electron/electron/blob/main/shell/browser/mac/electron_application.mm)). So on the first hotkey in an app, read `AXRole` and retry briefly, then set `AXManualAccessibility` once and keep it on for as long as that app runs, instead of toggling it per hotkey. ChatGPT for Mac is no longer native: since 9 Jul 2026 it is a Chromium build (bundle id `com.openai.codex`) that uses Chrome's application class and ignores `AXManualAccessibility`, and the old native app is now ChatGPT Classic. Chrome handles `AXEnhancedUserInterface` instead (full mode after the same delay of about 2 seconds), so for ChatGPT and Chrome use the `AXRole` trigger or `AXEnhancedUserInterface` ([Chrome source](https://chromium.googlesource.com/chromium/src/+/main/chrome/browser/chrome_browser_application_mac.mm)). Whether claude.ai and Lovable fields read on the first press in Chrome is a **[verify]** for spike (d). Safari exposes its tree without any attribute.
3. **Fallback:** synthetic Cmd+A, Cmd+C with the clipboard saved first and the alert sound muted, only when Accessibility returned nothing.
4. **Terminals** (Terminal, iTerm2, Ghostty, Warp running Claude Code) expose the whole buffer, not an input field, and Cmd+A selects scrollback. Require the user to select their prompt first. Never send Ctrl+C (it interrupts a running task) or Esc Esc (it can open the rewind menu) ([Claude Code interactive mode](https://code.claude.com/docs/en/interactive-mode)).
5. **Refuse** on secure fields (`AXSecureTextField`), when secure keyboard input is on, and in denylisted apps (password managers, banking apps the user adds).

### Rewrite

The runner sends the text, the target kind (Claude Code, chat app, app builder, other) and, only if the user granted the matching project folder, a compact context block (stack, scripts, relevant file paths, house rules) to the fast lane with the rubric from product section 5. The response streams into the card as the rewrite, a diff against the original, and at most one clarifying question. Guardrails: keep code, URLs, commands and pasted logs verbatim; cap growth (a rough prompt should not triple); a "light" style that fixes clarity only.

### Write back

Always paste; never set `AXValue` in web or Electron editors. Chromium (Chrome and every Electron or Chromium target, which covers Claude desktop, ChatGPT and Cursor) handles a value write on contenteditable content by setting `innerText`, which bypasses the editor's input events ([Blink ax_node_object.cc](https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/renderer/modules/accessibility/ax_node_object.cc)), so rich editors (ProseMirror, Lexical, Monaco style) are likely to ignore it in their own state (inference; verify per app). Current WebKit clears and inserts text through its editor instead ([WebKit source](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/accessibility/AccessibilityRenderObject.cpp); the [WebKit commit](https://webkit.googlesource.com/WebKit/+/124b6940f7b00c487ece349e9abd57e4747482c0%5E%21) cited earlier could not be opened on 7 Oct 2026), but behaviour still varies. Every shipping insertion tool pastes (Wispr Flow, Superwhisper, OpenWhispr; vendor docs).

1. Before writing, confirm the same process and focused element are still frontmost. If the user moved, copy to the clipboard and say so instead of pasting.
2. Save every pasteboard item, call `prepareForNewContents(with: .currentHostOnly)` (macOS 10.12+, exposed by `objc2-app-kit` 0.3.2) so Universal Clipboard never sends the text to the user's other devices ([currentHostOnly](https://developer.apple.com/documentation/appkit/nspasteboard/contentsoptions/currenthostonly)), write the new text marked with `org.nspasteboard.TransientType` and `org.nspasteboard.AutoGeneratedType` so clipboard managers ignore it ([nspasteboard.org](http://nspasteboard.org/)), post Cmd+A (only when replacing the whole field) and Cmd+V with `CGEventPost`, then restore the saved items after about half a second only if `changeCount` is still Companion's value.
3. In terminals the default is "copied; press Cmd+V", because Claude Code collapses long pastes and tells Claude the text was pasted rather than typed, following pasted instructions only where the typed message asks it to ([Claude Code interactive mode](https://code.claude.com/docs/en/interactive-mode)). Spike whether a pasted improved prompt is followed as well as a typed one. macOS 26.4 added Terminal paste protection, which can block a paste into Terminal, but reportedly only when Terminal has not been opened for more than 30 days, no developer tools are detected and the text came from a browser, Messages, Mail, Preview or a messaging app (secondhand, [MacRumors](https://www.macrumors.com/2026/06/16/apple-details-terminal-anti-scam-warning-in-macos/)), so the copy then Cmd+V flow should not trigger it; note it once in spike (d).
4. Keep the original for one click Restore; the target app's Cmd+Z is a second safety net.

### Focus is the whole trick

The panel is non activating, so the target app stays frontmost and Cmd+V lands in the user's field. Accept and dismiss must therefore be a mouse click on the card (clicking a non activating panel does not activate the app) or global hotkeys registered only while the card is visible (the same hotkey again to accept, Esc to dismiss). Registering Esc globally takes it from the user's app while the card is up, so register it only while the card is visible and release it the moment the card closes. Never make the panel key for this flow.

### Permissions and platform notes

* **Mac:** Accessibility only. Apple's engineers state that Accessibility covers examining other apps' UI and posting events ([Apple forums 820594](https://developer.apple.com/forums/thread/820594)). The global hotkey from `tauri-plugin-global-shortcut` uses Carbon `RegisterEventHotKey`, which needs no permission ([global-hotkey source](https://raw.githubusercontent.com/tauri-apps/global-hotkey/dev/src/platform_impl/macos/mod.rs)). Do not use global listeners like `rdev` here; they need Input Monitoring and break under secure input.
* **Pasteboard privacy:** macOS 15.4 previewed alerts when an app reads the pasteboard programmatically ([Michael Tsai](https://mjtsai.com/blog/2025/05/12/pasteboard-privacy-preview-in-macos-15-4), secondhand). Apple documents `NSPasteboard.AccessBehavior` since 15.4: the general pasteboard's default is "ask" on programmatic reads, a read that is both user originated and paste related is always allowed, writing does not trigger it, and the detect methods report what kinds of data are present without an alert; there is no documented exemption for Accessibility apps and no Info.plist opt out ([AccessBehavior](https://developer.apple.com/documentation/appkit/nspasteboard/accessbehavior-swift.enum/default)). The macOS 26 and 27.0 release notes say nothing about enforcement, but the macOS 27.2 beta release notes say the developer preview switch "has been removed", which could mean it is about to be on by default or that it was shelved ([macOS 27.2 release notes](https://developer.apple.com/documentation/macos-release-notes/macos-27_2-release-notes)). Companion is an Accessory app with no menu of its own, so its save step would always count as programmatic. Gate save and restore on `accessBehavior` **[verify]** on 27.2 in spike (d), since save and restore reads the clipboard. Prefer the Accessibility read so the clipboard is untouched whenever possible.
* **Windows:** read with UI Automation (`GetFocusedElement`, TextPattern selection or document range); write by `SendInput` paste: Ctrl+V normally, Ctrl+Shift+V in terminals, Shift+Insert in VS Code and Cursor (OpenWhispr's mapping, [OpenWhispr](https://docs.openwhispr.com/platform/editors-and-terminals), vendor). Mark clipboard data with `ExcludeClipboardContentFromMonitorProcessing` to keep it out of history and cloud sync ([Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats)). `SendInput` silently fails into elevated windows because of UIPI ([SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)); detect and explain. Chrome 138 made native UI Automation the default ([Chrome blog](https://developer.chrome.com/blog/windows-uia-support-update)).
* **Crates:** `objc2-application-services` (AXUIElement, trust check, messaging timeout) instead of the dormant `accessibility-ng` (0.1.6, May 2024); `macos-accessibility-client` optional for the trust prompt; `objc2-core-graphics` to post Cmd+V as CGEvents, rather than `enigo`, whose 0.6.1 release crashes on macOS when called off the main thread inside a Tauri app (the fix is unreleased), so call `enigo` only on the main thread if it is used at all; `objc2-app-kit` 0.3.2 for full pasteboard control, including `accessBehavior` and the detect methods; `uiautomation` on Windows. Read the source of `win-text-inject` (0.1.1, published 22 Jul 2026, 3 stars, no GitHub releases) before depending on it.

## 14. Show me how: capture once, let the model choose, let the machine aim

### Pipeline

1. **Hotkey.** The character turns to its "seeing your screen" state and the indicator lights **before** any capture.
2. **Capture (Rust).** One `SCScreenshotManager` capture (macOS 14+) of the display under the cursor, with `SCContentFilter(display:excludingApplications:exceptingWindows:)` excluding Companion's own windows and a denylist of apps (1Password, Bitwarden, Keychain Access, Apple Passwords, banking apps the user adds) so their pixels never exist ([SCScreenshotManager](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager); [SCContentFilter](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/init(display:excludingapplications:exceptingwindows:))). Do not rely on `sharingType = .none`; ScreenCaptureKit does not reliably honour it ([Apple forums 808016](https://developer.apple.com/forums/thread/808016)). Use `screencapturekit-rs` (MIT or Apache 2.0) rather than `xcap`, whose macOS path uses the deprecated `CGWindowListCreateImage` ([screencapturekit-rs](https://github.com/doom-fish/screencapturekit-rs); [xcap](https://github.com/nashaofu/xcap)). Keep the full resolution frame in memory only; never write it to disk. Claude Code may still write the image it receives to a temp image store **[verify]** in spike (e) (section 3, vision lane).
3. **Redact (Rust).** With Accessibility granted, black out secure text fields in the frontmost window. Refuse to capture while secure keyboard input is on. Run on device OCR (Vision `VNRecognizeTextRequest`, whose boxes are normalized with a lower left origin, so flip Y) and black out strings that look like card numbers (Luhn), IBANs, API keys and tokens (`sk-`, `ghp_`, JWTs). Tell the user how many items were blurred.
4. **Resize (Rust).** To a size that fits the model's image tier and Claude Code's own cap (default about 1280 px on the long edge; at most 2000 px for dense apps or 4K displays, because Claude Code caps user images at 2000 x 2000 px for Sonnet 5.5 and Opus 5.5, see section 3), so neither Claude Code nor the API resizes it and coordinates map one to one. Watch Retina scale factors per display; Clicky documents a bug where drawing at 2x silently doubled the image size.
5. **Ask (runner, vision lane).** Image first, then the question, the image size and the top OCR strings with ids as candidates. Claude calls `point_at`.
6. **Snap (Rust).** In order: the OCR box named by `ocrId`; else an Accessibility hit test at the mapped point (`AXUIElementCopyElementAtPosition`), walking up to the nearest actionable element (button, link, tab, menu item, text field) and accepting its frame if it contains the point and is a sane size; else a fuzzy match of `targetText` against OCR boxes within about 80 points; else the raw point with a larger "around here" ring. The hit test picks by window stacking order, so with the system wide element it can return Companion's own dock or overlay; hit test the target app's element (the app that owns the window under the point) or hide Companion's windows first, and expect a coarse first answer in Chrome, which builds its tree only when asked **[verify]** in spike (e) that the frames are useful in Vercel, Supabase and System Settings ([AXUIElementCopyElementAtPosition](https://developer.apple.com/documentation/applicationservices/1462077-axuielementcopyelementatposition)). If confidence is low or the target is tiny, one `zoom` pass on a crop cut from the full resolution frame already held in memory (no second capture). Never use `captureImage(in:)` (macOS 15.2+) for this: it takes only a screen rectangle and ignores the content filter, so Companion's own windows and excluded apps would appear in the crop. If a fresh capture is ever needed, use `captureImage(contentFilter:configuration:)` with a `sourceRect` ([captureImage(in:)](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager/captureimage(in:completionhandler:))). Only about 33% of Mac apps expose complete accessibility data ([MacPaw Screen2AX](https://research.macpaw.com/publications/screen2axvisionbasedapproachautomatic)), which is why OCR is the second signal.
7. **Draw.** One non activating, click through overlay panel per display (our own `NSPanel` created with `nonactivatingPanel`, plus `canJoinAllSpaces` and `fullScreenAuxiliary`, as in section 4; created hidden and shown only during a walkthrough). An arrow flies from the docked character to the snapped rectangle on a quadratic Bezier arc (Clicky's tuning: duration distance/800 clamped to 0.6 to 1.4 s, arc up to 80 px), then a pulsing ring around the rectangle and a short caption, held until the step completes or about ten seconds pass.
8. **Walkthrough loop.** Only while walkthrough mode is visibly on: advance when a mouse down lands inside the target rectangle, or on a "next" hotkey or the voice word "done"; wait about 400 ms for the UI to settle; capture again with the indicator still lit; ask for the next step with a short text history. End on `finish`, Esc, a step limit, or about two minutes idle.

Coordinate mapping: model pixels to display points (divide by the resize factor), CG global coordinates have a top left origin while AppKit's `NSScreen.frame` has a bottom left origin (match displays by `CGDirectDisplayID`), and overlay CSS pixels equal points on macOS.

## 15. Voice: hold to talk, transcribe on the device

Claude's supported inputs are images, PDFs and text, not audio ([Files](https://platform.claude.com/docs/en/build-with-claude/files)). Claude Code's `/voice` dictation streams audio to Anthropic, requires a Claude.ai login and does not work with an API key ([Voice dictation](https://code.claude.com/docs/en/voice-dictation.md)), and it is a terminal feature, not an SDK call. So Companion transcribes in Rust and sends only text.

* **Engine.** whisper.cpp through Rust bindings: Metal and Core ML acceleration on Apple Silicon, Silero voice activity detection, about 99 languages including Hindi; model sizes tiny 75 MiB, base 142 MiB, small 466 MiB (about 852 MB RAM) ([whisper.cpp](https://github.com/ggml-org/whisper.cpp)). Default `base` or `small` quantized, downloaded when the user turns voice on, never bundled in the DMG. The `whisper-rs` GitHub repository was archived on 30 Jul 2025 and the project moved to Codeberg, where it has had no commits since March 2026 ([whisper-rs](https://github.com/tazz4843/whisper-rs)). Use `whisper-rs` 0.16.0 (12 Mar 2026, Unlicense) from crates.io with the `metal` feature turned on explicitly, since it is off by default. It bundles whisper.cpp v1.8.3 while upstream is at v1.9.5 and has open memory leak reports, so pin and vendor it ([whisper-rs on Codeberg](https://codeberg.org/tazz4843/whisper-rs)). Run voice activity detection through `WhisperVadContext`, because VAD switched on through `FullParams` silently does nothing ([whisper-rs#242](https://codeberg.org/tazz4843/whisper-rs/issues/242)). Building it needs the `cmake` binary (`brew install cmake`) and libclang (in Command Line Tools). Plan B is `transcribe-cpp` (MIT, actively developed, with a `metal` feature), which Handy now uses for Whisper models.
* **Reference app.** Handy (MIT, v0.9.8, Oct 2026) is a push to talk dictation app on Tauri, React and Rust, shipping on Mac and Windows ([Handy](https://github.com/cjpais/handy)). It now runs Whisper models through `transcribe-cpp` (ggml, Metal) and Parakeet and similar models through `transcribe-rs` (ONNX), with `cpal` audio capture, Silero VAD (`vad-rs`) and `rubato` resampling, and it uses the tauri-nspanel v2.1 branch. Read it before writing the voice module. Its default macOS hotkey backend is its own `handy-keys`, an event tap that needs Accessibility (it does not use `rdev`). Use the Tauri global shortcut plugin instead, which Handy offers as an option and as its Secure Input fallback, because it needs no permission. The plugin cannot register `fn` (Globe) or a modifier only hold such as Right Option, because Carbon hotkeys need a normal key, so hold to talk defaults must include one.
* **Flow.** Key down opens the microphone (the macOS orange dot shows only now) and the character turns to Listening with a waveform; key up closes it; the transcript appears in the ask box for a glance; Enter sends, or auto send when turned on and the transcript has three or more words (Claude Code's own rule). Never keep the microphone open otherwise; no wake word.
* **Permission.** `NSMicrophoneUsageDescription` in `src-tauri/Info.plist` (merged into the bundle) and the system prompt on first use, plus the `com.apple.security.device.audio-input` entitlement in the entitlements file set by `bundle.macOS.entitlements`, because Tauri enables hardened runtime by default and a signed build without it is expected to record silence or be denied with no error ([audio-input entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.device.audio-input)). Check authorization before opening the stream, and treat all zero buffers as "microphone blocked", not silence. Claude Code's docs show users hitting a missing microphone entry; build a recovery screen that runs or shows `tccutil reset Microphone <Companion bundle id>` (never without the id, which revokes microphone access from every app on the Mac), then asks the user to fully quit and relaunch Companion so macOS prompts again ([Voice dictation](https://code.claude.com/docs/en/voice-dictation.md)).
* **Windows.** The built in dictation grammar runs on a Microsoft web service ([Microsoft Learn](https://learn.microsoft.com/en-us/windows/apps/design/input/speech-recognition)), so use the same local whisper code.
* **Later engine.** Apple's SpeechAnalyzer and SpeechTranscriber need macOS 26, download their own assets, and launched with about 10 languages (no Hindi) ([Apple](https://developer.apple.com/documentation/speech/speechtranscriber.md)); one third party benchmark found them more accurate and faster than Whisper Small on English (secondhand). Add as an optional engine on macOS 26 after v1.
* **Wispr Flow and macOS Dictation.** Both insert text by pasting into the focused field. The ask box must be a plain text input that accepts paste and never swallows Cmd+V; test both. Wispr Flow's MCP server (meeting notes, transcripts, calendar; read only; not dictation history) can be offered as a connector ([Wispr Flow MCP](https://docs.wisprflow.ai/articles/9551372685-connect-an-mcp-client-to-wispr-flow-remote-mcp-server)).
* **Speaking back.** Off by default. An opt in reads short status lines with `AVSpeechSynthesizer` system voices on Mac.

MCP tools need explicit `allowedTools` entries (`acceptEdits` does not approve them), and any send, pay or delete tool must carry `_meta["anthropic/requiresUserInteraction"]` so it can never run unattended ([SDK permissions](https://code.claude.com/docs/en/agent-sdk/permissions)). Text from email and web pages is attacker writable: treat it as data, keep tools minimal in any session that reads it, and never combine private data, untrusted content and an outbound send in one unattended run ([Simon Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)).

### Loop Closer pipeline

1. **Scope:** messages the user **sent** in the last 14 to 30 days, the user's requests to Companion, and granted folders. Nothing else by default.
2. **Prefilter** locally with keywords ("I'll", "will send", "by Friday", "let you know") to cut volume.
3. **Extract** with the fast lane into a strict schema: who promised, to whom, what, deadline, the quoted span, confidence.
4. **Closure check:** search the same thread, later sent mail and granted files for evidence it was done (an attachment, a link, a reply); drop if closed.
5. **Surface** at most three high confidence items a day, past or near their deadline, each showing the quoted sentence and its source as the receipt; a thumbs down trains a per user filter stored locally.
6. **Act:** draft the follow up and propose a time; sending always needs a tap.
7. **Stalled projects:** a granted project folder with activity followed by N weeks of quiet (default three) gets one nudge with a Rescue offer, then silence if dismissed.

Expect precision to be the problem: commitments were about 5% of email sentences in Microsoft Research's study, with a best F1 of about 0.8 and annotator agreement of alpha 0.73 ([Microsoft Research](https://microsoft.com/en-us/research/uploads/prod/2019/01/AzarbonyadWSDM2019.pdf)). Ship it first as "what did I promise this week?" on request plus an opt in daily digest.

### Pattern Catcher pipeline

1. **Label:** after each task, the fast lane assigns a short normalized intent label ("append invoice totals to sheet") and the runner stores the task's tool call signature (the ordered tool names and target kinds). No embeddings service is needed under bring your own Claude; labels plus signatures are enough for v1.1 (design choice, revisit with a local embedding model if recall is poor).
2. **Cluster weekly:** flag a label or signature seen three or more times over two or more weeks, and file patterns from FSEvents (same folder, same weekday, same follow up change).
3. **Offer** with evidence ("you asked me this on 3, 10 and 17 Sept") in the digest or on request, never as an interruption.
4. **Approve** into a saved task: prompt, exact `allowedTools` (no bare `Bash`), `disallowedTools`, MCP servers, working directory, trigger (time or folder event), budget, and the approval time. Where steps are fixed (file moves, sheet appends), compile to a plain script the user can read instead of running an agent.
5. **Optional later:** a "show me once" recorder the user starts, with a visible indicator and automatic stop, capturing only that demonstration.

### Running saved tasks

* `permissionMode: "dontAsk"`: listed tools run and anything that would prompt is denied without calling back; a `PreToolUse` hook is the hard gate; never `bypassPermissions`, which `allowedTools` "does not constrain" ([SDK permissions](https://code.claude.com/docs/en/agent-sdk/permissions)).
* The SDK has no scheduler; the Rust core owns timers and FSEvents triggers and asks the runner to start the task. If Companion is quit, nothing runs (a launchd agent would fix that but is a heavier trust ask; later).
* Every run snapshots first if it touches a project, writes a receipt, counts against a per task daily budget, and pauses itself after two failures with a card explaining why.
* Each run spends the user's Claude; show it in the receipt and the weekly recap.

## 20. Open technical questions

## Conclusion

The model integration is the easy part: the Agent SDK already exposes what a supervisor needs, and the binding constraint is legal rather than technical, which makes "bring your own Claude" the foundation. The real engineering sits in the operating system: a panel that behaves like part of macOS, an Anthropic signed binary shipped without alteration, text read and pasted in other apps without breaking their editors, a pointer that lands on the right button, a microphone that opens only while a key is held, and an undo that is honest about what it cannot undo.

Because safety, snapshots, proof, memory, approvals and the privacy rules live outside the engine, every feature is a thin client of one core: Drive, Rescue and Ship are agent sessions; Prompt help, Where was I and recaps are fast lane calls; Show me how is a vision session with two tools; Loop Closer and Pattern Catcher are scheduled, allowlisted tasks over the same task log. So sequence ruthlessly: retire the operating system risks in M0, build the runner, shell and proof core once, treat the headless suites as the product's spine, and add features in the order of section 18.


### Noticing a click without a permission (checked 11 Oct 2026, M10 your turn)
A throwaway app with a fresh bundle id and no permissions (`AXIsProcessTrusted()` false) polled `NSEvent.pressedMouseButtons` and `NSEvent.mouseLocation` every 16 ms. A 150 ms press in TextEdit, another app, was seen with its position. A synthetic click with no hold was missed (too short for the poll). So Companion's "your turn" needs no Input Monitoring and no Accessibility to notice a click; it polls only while the ring is up and never reads keys.
