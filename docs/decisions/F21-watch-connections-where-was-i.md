# F21: Watch routines, builder stack connections (read only) and Where was I (22 Oct 2026)

- **Status:** Founder decision, 22 Oct 2026 ("start building on it"). Unparks three things F18 kept out of the launch. Everything else F18 parked stays parked (agents with memory, email and calendar connections, ads and CRM, dictation into any app, clicking for you).
- **Why:** the product needs a reason to be opened when nothing is broken, and a reason to pay. Chat is free everywhere; a helper that watches the things you built and tells you the moment one breaks, with proof, is not.

## Decision
1. **Watch routines.** The person adds checks for a project on a schedule they choose: is my site answering, did the last deploy fail, is CI red, do my project's own checks still pass. They run only while Companion is open (no login item, no background service), read only, and never change anything. Results show in Home and the island (a plain line, never a popup that takes focus). A failed watch offers Fix it (a normal task, started by the person's press) with the evidence. Watches never call Claude, so they cost nothing.
2. **Builder stack connections, read only.** For a project linked to Vercel or GitHub, Companion reads deployments, build logs and CI status through the person's own `vercel` and `gh` tools, as it already does for failed deploys. Companion never stores their tokens (their tool holds them), never writes anything, and never deploys (Ship keeps its own tap rules). Supabase stays read only through what is already built until a safe read only path is proven.
3. **Where was I.** Opening Companion after time away tells the person what they were doing in this project and what is unfinished (last tasks, failed checks, open questions, watch alerts), built on what already exists (recap, task log, memory), on the person's press or on open, never in the background.
4. **Rule 6 is amended (founder decision):** "Only exception: a source the user explicitly connected for Loop Closer or Pattern Catcher" becomes "...for Loop Closer, Pattern Catcher or Watch routines". Read on the user's schedule or request while Companion is open, only through the person's own tools or their own web address, nothing indexed beyond the latest result, deleted when the watch is removed.
5. **Rules that stay:** nothing sends, pays, deploys or deletes without a tap (rule 13); no screen or microphone in the background (rule 5); no secrets stored by us (rule 2 spirit); Stop everything stops running watches; every watch is a setting-backed, plain list the person can read, edit, pause or delete; Delete everything removes them.
6. **Group:** Watch routines and Where was I belong to Flow (they are about your work); the connections feed Flow's Rescue and Fix. All switchable.
7. **Free and paid (open, for later):** the first few watches free, more watches and shorter schedules in the paid tier. Not built now.

## Built (logic first, 22 Oct 2026, branch m13/watch)
The engines, protocol, settings and tests are built; the pages are plain rows in the existing Settings and Home (no new look, no docking or animation work). Not tried by a person on a real Mac yet (see "Not proven").

- **Watch routines** (`runner/src/watch.ts`, `watchsite.ts`, `watchaddress.ts`, `watchwire.ts`). Four kinds: `site_up`, `deploy_status`, `ci_status`, `project_checks`. Schedules `5m`, `15m`, `30m`, `1h` and `daily@H`; nothing shorter than 5 minutes. At most 10 watches per project and 30 in all; the same thing twice is refused. The scheduler ticks (every 30 seconds) only while the engine runs. A missed time runs once on wake. Jitter: up to a tenth of the schedule, at most a minute. Never two checks of one watch at once; at most 3 at a time. A check that takes too long is stopped: a site is then failing, a tool is unknown. A clock set back is not waited out: a check planned later than one schedule from now (plus its spread and 5 minutes) is due at once. A last check dated in the future is ignored when the engine starts. States: ok, failing, unknown (with the plain line and what to do), paused. One alert when a watch goes to failing, one recovered when it is fine again, nothing in between. Quiet hours hold alerts back, still check, and a failure that lasts is told once when they end. The history is the last 20 states a watch has been in (a new entry only when the state changes); the latest result and the history are all that is kept, in `watch.json` (owner only, written whole, a damaged file moved aside, Delete everything removes it).
- **The project's own checks for a watch** (`agent.ts` `checkWithoutModel`, `proof/livefiles.ts`). The proof ladder's build and tests, with no model, no installs and no server or browser (`noServer`). It runs only scripts the person has already allowed: if the project has no record of allowed scripts (no check or task of theirs has run there), or the scripts changed since, nothing runs and the watch says so (cannot tell, with what to do). Each command ends with Companion (`endWithUs`). It takes no checkpoint (it reads the few files that decide what may run straight from the folder), so a check every few minutes adds nothing to Undo. It never holds the project: the person's own task, undo, install or check on the folder ends it (it is tried again in 2 minutes), so nobody waits for a watch or presses Stop for one. Fix it from a watch always answers: after Stop everything, or 2 minutes without evidence, the page gets `watch.evidence` with `stopped` and the watch's own words, and starts no task.
- **The site check**: one GET of the address the person typed. http and https only, no cookies, no body read or kept, at most 3 redirects, a second try after a short wait before it counts as failing. Every hop must be a public address; this Mac itself only when the person typed localhost (not a number that reads as 127.0.0.1); a name that leads to a private address is refused. A name is looked up once per hop, every answer judged, and the request is made to the first one (node's own http client with that address, the name kept for Host and the certificate; no proxy from the environment is used), so a name that answers differently the second time cannot lead elsewhere. A name ending .localhost that the person did not type is looked up like any other. IPv6 forms that carry an IPv4 address (mapped, compatible, NAT64, 6to4) are judged by the address inside; Teredo, site local, discard, documentation and the IPv4 special ranges (198.18/15, 192.0.0/24, the documentation ranges, 240/4) are never visited. An address Companion refuses, or a name that leads nowhere, is "cannot tell", never "failing" (it says nothing about the site). The address is kept without a part after `?` (such an address is refused when typed, and cut off a saved one on load), because keys go there and Companion keeps no secrets. Any answer under 400 is up; 400 and over is failing, with the number.
- **Connections, read only** (`connections.ts`, `readonly.ts`). `refuseWrite` is the check in code: only `vercel list`, `ls`, `inspect` and `gh run list`, `run view`, `repo view` pass, and every write verb (deploy, promote, rollback, env add or rm, run rerun, workflow run, pr or issue create, and the rest) and anything joined to them is refused before a command is run. Output is redacted with `redact.ts` and capped. Rescue now also reads the failing GitHub run (setting `rescue.readCiRun`, on). Fix it from a failed watch asks for the evidence (`watch.fix`); the page starts an ordinary task only on the person's press. Supabase: nothing added.
- **Where was I** (`wherewasi.ts`, command `where.was.i`, answer `where.ready`). What you were doing, what is unfinished (a failing watch, a failed check, a waiting question, plan or approval), what changed since, and one next step as a button. No model. Offered when Home opens after the break set in **Show Where was I after a break of** (`where.after`, usual 30 minutes, off possible; this is the old `recap.after`, renamed, and an old value carries over). With Flow off, the older three line `recap.ask` (core) is asked instead. "Files changed outside Companion" is not told: nothing watches the folder outside a running plan, so there is nothing true to say.
- **Group**: all of it is in Flow (`protocol/groups.json`: `watch`, `connections`, `whereWasI`). Flow off refuses the commands with the one plain line, stops running checks and the schedule; taking a watch away (`watch.remove`) still works.
- **Settings**: `watch.on`, `watch.schedule`, `watch.dailyHour`, `watch.quiet`, `watch.quietFrom`, `watch.quietTo`, `rescue.readCiRun`, `where.after`.

## Not proven (needs a real Mac and the real tools)
- A watch of each kind against a real site, a real Vercel project and a real GitHub repository, with the real `vercel` and `gh` (their exact error words for "not signed in" and "not a project" are matched from memory and by tests with stand ins).
- The pinned connection is proven against a server on this Mac's own loopback, not against a real site over https (the name is kept for the certificate by node, not tried here). A Mac that is offline looks the same as a site that is down for a plain GET (both fail to connect), so Wi-Fi off can alert.
- The Watch list, the island line and the Where was I button on screen.
- That a Mac asleep and woken runs one check, not many (proven here with a test clock, not with sleep).
