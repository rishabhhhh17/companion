# F19: Drop a file on the companion to convert it (20 Oct 2026)

- **Status:** Amended by F28 (30 Oct 2026, default switch only): the Files group switch (`files.on`) now starts off. The rest of this record stands. Founder decision, 20 Oct 2026. Adds to F17's "works on any app" screen features. Not to be reopened without the founder.
- **Source:** the founder, after a Tangerine reel (hold Shift while dragging a file, a circular menu of conversions): "I wanna build this into the normal screen HeyClicky feature list."

## Decision
1. **The trigger is a drop onto Companion's own windows:** the character or the island in the notch. Hold Shift while dragging anywhere is not possible: it needs key events and watching every drag (AGENTS.md rules 5 and 8). The character comes to meet a file being dragged over it only once the drag is over Companion's own window.
2. **A circular menu of what can be done with that file,** chosen by its type, all on the Mac with nothing uploaded: images (convert between PNG, JPEG, HEIC, WebP, TIFF; resize; compress), PDFs (merge, split, compress, pages to images), documents (to PDF, plain text, between Word, RTF and HTML), audio and video (the formats the Mac converts by itself; trim).
3. **Never over the original.** The result goes next to the original with a new name, never replaces it, and a Show in Finder line appears. Nothing is deleted.
4. **Built in Mac tools first.** Wider video and audio formats need ffmpeg, which has a licence question: the founder decides before it is added.
5. **Customizable** through the settings registry: on or off, default format choices, where results go (next to the original by default).
6. Off the record by nature: no file content goes to Claude or anywhere else; nothing is kept.

## How it is built (M11, 20 Oct 2026)
- **Where the drop is seen:** Tauri's own drop events on the character's window and the island only (`convert.rs`, wired in `main.rs` setup). A drag of files over one of them lights it; a drag of text, a link or a picture from another app (Photos, Mail, a browser) brings no file, so it neither lights the character nor opens anything. Nothing watches drags anywhere else and nothing reads keys. Home keeps its own page drop, which adds a file to the ask box as before. A drop on the island opens Home, where its choices are.
- **The menu:** a ring of round choices around the character (`dropRing.tsx`, `role="menu"`), and the same choices as a list on Home's Now tab, because the character's window never takes the keyboard (rule 9). Home is also where a trim's two times are typed; Trim on the ring opens Home for them. The character grows and lights while a file is over it, and only lights with reduced motion.
- **The actions:** pictures convert between PNG, JPEG, HEIC and TIFF (WebP is offered only when `sips --formats` says this Mac can write it; on macOS 27.0.1 it can read WebP but not write it), resize (longest side 1024, 1600 or 2400 pixels, never made bigger) and compress (JPEG, or HEIC for a HEIC; kept only when the result is smaller than the original, since a picture already saved small comes out bigger). PDFs merge (several dropped), split into one PDF per page, compress (the Mac's Reduce File Size filter, kept only when smaller: a PDF of words only does not shrink) and save each page as a picture. Documents (Word, RTF, HTML, plain text, old Word, OpenDocument text) go to PDF, plain text, Word, RTF and HTML. Sound goes between M4A, WAV and AIFF and can be trimmed; video between MP4 and MOV, keep only the sound, and trim. Several files of one kind get each action on each file, except a file already in the format asked for, which is left as it is; trim is one file at a time. The end line says how many files were left as they were.
- **The tools:** `sips`, `textutil` (always with `-noload`, which stops a web page fetching anything from the network), `afconvert`, `avconvert`, and one fixed PDFKit script run by `osascript -l JavaScript` for the PDF jobs and for printing a document to PDF. All are argument lists with absolute paths, never a shell string, with a plain environment, each in a process group of its own so Stop ends anything a tool started. No new dependency, no ffmpeg.
- **Corrected 20 Oct 2026 (review):** `-noload` does not stop a web page reading pictures from this Mac, by a full path or one relative to the page. Converting it to RTFD copied them in, and the PDF then carried them (checked on a real Mac: a page pointing at a picture in another folder gave a PDF with that picture in it). The Mac's reader also takes a web page saved as .doc, .docx or .odt as a web page. So a document now goes to PDF through plain RTF, which keeps the words and their look and no pictures. Checked on the same Mac: Word, OpenDocument and RTF files that link to a picture elsewhere did not bring it in. The cost is that no picture reaches the PDF, also one stored inside the document; in the same check the Mac's reader brought none into RTFD from a hand made Word file or an RTF file with a picture inside, so little may be lost, but a real Word file with pictures was not tried (see Not proven). The plain text, Word, RTF and HTML results never carried such a picture.
- **Never over the original:** each tool writes into a private work folder in the Mac's temporary folder; the result is then put next to the original (or in Downloads or on the Desktop, from Settings) under the first free name, "photo (converted).png", then "photo (converted 2).png", by a link or a copy made new that fails rather than replace a file. A split or pages to pictures makes a new folder, "report (pages)"; if a page cannot go in, or the job is stopped part way, that folder (made just then, Companion's own) is taken away whole. Where the result goes is checked first, so nothing runs for a result that could not be saved (a disk image, a share that is read only). Just before the tools run, each dropped file they read (every PDF of a merge, not only the first) is opened once without following a link, checked to be a regular file, and copied into the work folder (an instant clone on the same disk, else a copy; a file over 512 MB on another disk is read where it is, after the same check by its path). The tools only ever read that copy, so a file swapped after the drop changes nothing, and a web page's relative links point into the work folder, where nothing else is. The work folder is removed after every job; nothing else is ever deleted.
- **Stop:** one job at a time, with progress (results done, and the tool's own percentage when it gives one); a drop while one runs changes nothing. The menu's Stop and Stop everything end the tool and anything it started; nothing half made is put anywhere. What was made before the Stop stays (it is new and replaces nothing) and is named, with Show in Finder. Quitting (the menu bar, Delete everything, macOS) stops a running job and waits up to two seconds for its tool to end and its work folder to go; a work folder left by a Companion that was ended mid job is removed at the next launch.
- **Settings** (section Dropped files, `drop.*`): Drop a file on the character to convert it (on), the format offered first for pictures, documents, sound and video, the resize size, how much to compress, and where new files go (next to the original).
- **Off the record:** the pages get the files' names only, never their paths; nothing goes to the engine, Claude or the network; the activity log names no file.

## Not proven (needs a real Mac)
- Dropping a real file from Finder on the character and on the island in the built app: that Tauri's drop events arrive on these borderless, non activating panels, that the hover lights, and that a drop on the island opens Home.
- The ring's look and fit in the character's 160 point window at every edge, VoiceOver reading the ring and the list, and the keyboard on Home's list.
- Video conversion, Keep only the sound and trim on a real video, and how long a long video takes. Pictures, documents to HTML and PDF, PDF merge, split, compress and pages to pictures, and sound conversion and trim ran for real on files in a temporary folder in the tests; Show in Finder did not run in a test.
- A result going to Downloads or the Desktop, and a folder Companion cannot write to (the check before any tool runs was tested with a folder made read only, not a real disk image or share).
- Whether a real Word file with pictures inside kept them in its PDF before the move to plain RTF (if it did, Document to PDF now leaves them out, and a way to keep a document's own pictures and nothing else would be needed).
- A file on another disk: the copy, reading a file over 512 MB where it is, and the real copy for a zip, ran in the tests only by forcing that path on the same disk. The free space check was tested with room given by the test, not on a nearly full disk.
- Quitting from the menu bar, and Delete everything, while a long video converts: waiting for the job was tested in the shell's tests, not in the built app.

## More formats with the Mac's own tools (M13, 21 Oct 2026)
Still no ffmpeg and nothing bundled or downloaded: only tools already on every Mac. Every format is offered only after a runtime check that this Mac can write it (`Caps::probe` reads the tools' own lists once, the first time anything is dropped; `Caps::core` is the few every Mac has, which is also what is assumed when a tool says nothing). Nothing is converted to find out.

**Probe, run on macOS 27.0.1 (the app minimum is macOS 14, so every extra format below is checked at run time):**

| Tool | Reads | Writes (this Mac) | Offered |
|---|---|---|---|
| `sips` | PNG, JPEG, HEIC, TIFF, GIF, BMP, JPEG 2000, TGA, AVIF, ICNS, ICO, WebP, JPEG XL, camera RAW and more | PNG, JPEG, HEIC, TIFF, GIF, BMP, JPEG 2000, TGA, AVIF, ICNS, ICO, PDF, PSD, EXR, DDS and more; not WebP, not JPEG XL | PNG, JPEG, HEIC, TIFF, WebP (if writable), GIF, BMP, JPEG 2000, TGA, AVIF, ICNS and ICO (square pictures only), turn, flip, grey (Generic Gray profile), resize, compress |
| ImageIO and PDFKit (fixed JavaScript for Automation scripts through `osascript`) | pictures, PDFs | PNG thumbnails, a picture saved again without place, camera and author details (also the text and XMP a PNG carries), PDFs from pictures, rotated PDFs, PDFs with pages taken out, the words of a PDF as text | strip details (PNG, JPEG, HEIC, TIFF), set of small sizes (64, 128, 256, 512, only those smaller than the picture), pictures to one PDF or one each, rotate, take out first or last page, keep first page, PDF words to text |
| `afconvert` | AIFF, WAV, CAF, M4A, MP3, AAC, FLAC, AU and more | M4A (AAC), M4A (ALAC), WAV, AIFF, CAF, FLAC, AAC (ADTS) | all of these as formats, mono, stereo, a sample rate (setting `drop.sampleRate`), trim (existing). A data format counts only inside the file format that lists it (`audio_ok`) |
| `textutil` | txt, rtf, rtfd, html, doc, docx, odt, wordml, webarchive | txt, rtf, html, doc, docx, odt, wordml (as .xml) | all of these between each other; markdown (.md) is read as plain text with `-format txt` and nothing is rendered; PDF from any of them through plain RTF as before. RTFD and web archive are never written: they carry pictures from elsewhere on the Mac |
| `avconvert` | MOV, MP4, M4V | presets on this Mac include 640x480, 1280x720, 1920x1080, HEVC, ProRes, M4A | MP4, MOV, M4V, HEVC, 480p, 720p, 1080p (HEVC and the sizes are kept only when the result is smaller: the label says smaller; a plain format change is not held to that), keep only the sound, trim |
| AVFoundation (the picture script) | video | a still PNG at the start or the middle | still frame |
| `ditto` | zip | zip | zip a file or folder (no links followed, no resource forks or extended attributes), several into one zip, unzip into a new folder |

**Zip safety.** A zip is read before anything is extracted (`zip_vet`). ditto does not use the zip's list: it reads each file's own header one after another. So the pieces must follow each other exactly from the first byte to the start of the list, each with the name and the size the list gives it, with nothing between them and nothing the list does not name, and the list must end exactly where the end record starts. The mode bits count whatever system the zip says it was made on (ditto reads them for any), so a link in a zip said to be made on Windows is refused too. It is refused for a path that climbs out (`..`, absolute, backslash or drive letter), a link or any non file and folder entry, a password, more than 10,000 files or 4 GiB once opened by what it says, and zip64 sizes (not read at all). While ditto runs, the folder it writes is looked at five times a second (`Guard`) and the tool is ended the moment the caps are passed or a link appears. What is unzipped keeps the zip's "downloaded from the internet" mark, so macOS still checks it. A folder to zip is copied first without following any link, capped at 100,000 things and 16 GiB, and nested no deeper than 64; a pipe, socket or device in it refuses the folder ("special") rather than being skipped or waited on.

**Review fixes (21 Oct 2026).** (1) A file that is zipped, and a zip that is opened, is always a real copy in the work folder, never a link to where it is: a zip stores a link as a link (it would hold only the path of the original), and an unzip must vet the very bytes it extracts. Over 16 GiB (zip) or 4 GiB (unzip) that cannot be cloned, it is refused ("tooBig"). Only tools that merely look at a file (a long video on another disk, over 512 MB) still read it where it is. (2) Room: before a copy, a zip or an unzip, the free space on the work folder's disk (`statvfs`) must cover the size plus 256 MiB, twice the size when a copy is made and then zipped; otherwise "noRoom" for that file, nothing changed. (3) Folders nobody can write in (mode 0555 from a cloned folder or from a zip) are made ours to change before they are removed (`remove_tree`, used for the work folder, a failed copy, a failed result folder and the launch sweep), so no space is lost for good; the copy made for a zip is made ours right away. (4) Flips are made on the picture as it is seen: for pictures stored on their side (Orientation 5 to 8, read through ImageIO because sips has no such property) left to right and top to bottom swap, since sips flips the stored pixels and keeps the tag. (5) Taking off details also clears a PNG's text (author, description, software) and XMP; what stays is the picture, its size and colour profile. (6) Convert to HEVC is kept only when smaller.

**Not possible without ffmpeg (the exact gap, for the founder and the lawyer):**
- MP3 output. `afconvert` lists MP3 but this Mac has no encoder: `afconvert -f MPG3 -d .mp3` fails with "fmt?" (checked).
- Ogg Vorbis and Opus output. Listed, and also fail the same way (checked).
- WebP output (sips reads, does not write), JPEG XL output.
- WebM, MKV, AVI, WMV, FLV video and WMA, OGG audio, in either direction.
- ProRes is a preset on this Mac, but it makes very large files and was left out on purpose, not for lack of a tool.
- Subtitles, GIF from video, extracting only a time range of frames: no built in tool.
- Markdown rendered as a formatted page: the Mac has no renderer, so Markdown is treated as plain text and the PDF shows its marks as typed. PDF page choices are first page, last page and keep first page; other ranges need a way to type them (not built).

**Settings.** New: `drop.sampleRate`. New choices on existing ones: picture format GIF, BMP, JPEG 2000; document format old Word and OpenDocument; sound format ALAC, CAF, FLAC; video format M4V. A first choice the Mac cannot write is simply not first. The Files group switch (`files.on`) and `drop.on` still turn everything off.

**Not proven (needs a real Mac).** The ring with up to about 25 round choices in the 160 point window (a layout and styling job, not done here), VoiceOver reading the longer list, older macOS versions where fewer formats exist (the runtime check covers them in logic; only macOS 27 ran), HEIC details stripping and HEVC output on a real long video, zip of a folder on another disk or over 512 MB, dropping a real folder from Finder on the character.
