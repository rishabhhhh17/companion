# T02. Engine: the Claude Agent SDK, pinned to an exact version

- **Status:** Accepted from research; open items checked in M0 spikes (b) and (g). Updated 7 Oct 2026 after desk research and review.
- **Date:** 2026-10-06
- **Source:** technical_research.md section 1, row 2; section 3 (also section 1 prototype lesson four, section 19 pitfalls 1, 2, 8 and 28, section 20 questions 2 and 16); M0-desk-research-details.md sections (b), (c) and (g)
- **Related:** F03, F10, T03, T04, T05, T06, T10

## Decision
The runner drives Claude Code through the Claude Agent SDK for TypeScript, `@anthropic-ai/claude-agent-sdk`, pinned exactly to 0.3.291 (it bundles Claude Code 2.1.291). Each agent card gets one streaming input `query()`.

## Why
- The SDK already gives a supervisor what it needs: hooks, permission modes, budget caps, interrupt, resume, sandbox and image input (section 1, row 2).
- Streaming input lets the user add "also make it blue" mid run, and images reach Claude only in streaming input mode (section 3).
- Each SDK patch moves the bundled Claude Code version and can change behaviour silently (pitfall 28). M0 keeps 0.3.291 even though 0.3.292 shipped on 6 Oct 2026.
- The prototype spawned a fresh `node` process per step: no session continuity, no interjection, a cold start every step (prototype lesson four).

## Alternatives considered
- Our own loop on the Messages API: later. It is the only route to managed credits; confirm with Anthropic sales before building billing (section 3).
- A Codex engine through `codex app-server`: a later adapter behind the same `Engine` interface (section 3).

## What this means for the build
The full option set is in technical_research.md section 3. Rules a coding agent must never miss:
- Pin the exact version, no caret, and upgrade only on a branch with the full headless suite. Always run the SDK's bundled binary, never a `claude` on `PATH`.
- Safety, checkpoints, proof, receipts and approvals live in the runner core; engines are thin adapters.
- `env` replaces the environment. `buildChildEnv()` starts from `process.env`, sets the login shell `PATH` (T04) and `CLAUDE_AGENT_SDK_CLIENT_APP`, and adds `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, `DISABLE_UPDATES=1` and `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`. The scrub strips credentials from the subprocesses Claude Code starts (Bash commands, hooks, stdio MCP servers) while Claude Code keeps them for its own API calls; it leaves GitHub tokens and proxy settings (env var docs).
- The runner's own spawns (dev server, Playwright, gitleaks, its own package installs) get no `ANTHROPIC_*` keys. M1 test: an agent Bash `env` shows no `ANTHROPIC_API_KEY`.
- Every session sets `settingSources` explicitly (`["project"]` for agents) and `strictMcpConfig: true`, or a plan login loads the user's claude.ai connectors; approved project servers go in `mcpServers` (T05). Agents use the `claude_code` prompt preset with `append`.
- `interrupt()` is Stop; `abortController` is the hard kill on quit. Persist `session_id` per card and `resume` after a restart.
- Validate the project folder before spawning (pitfall 2). Map all 13 error values to plain sentences, with a fallback.
- Modes: `acceptEdits` normally, `plan` for Drive planning, `auto` only as an experiment, `bypassPermissions` never.
- Fuses: `maxBudgetUsd` and `maxTurns: 80`. Cost fields are estimates; never sum them across resumed calls (pitfall 8; T10).
- `prewarm()` is alpha and freezes most options; use it only after they settle.

## What the build settled (follow ups, 16 Oct 2026)
- A follow up from the card (`agent.send`) is not streamed into a running `query()`. It is refused while the agent or its project is busy, and once the task has ended it runs as a new task that resumes the last task's session (`resume`), so it gets its own snapshot, the same safety rules, the proof ladder, a receipt, cost booked to the day and the daily limit. Try again (`agent.send` with `retry`) is the same, with the last failing check as evidence. This differs from the streaming input design above and in technical_research.md section 3 ("fed by agent.send"): interjecting while a task runs ("also make it blue" mid run) is not built. Stop, then a follow up, does that job with a clear undo point.
- `agent.send` now names its project, so the app holds it to the folder the person chose (project bound in `app/src-tauri/src/runner.rs`), and the runner refuses it for any project other than the last task's.
- Off the record tasks keep no session (`persistSession: false`), so a follow up or Try again starts a fresh session and is told the request again. The last task's request is kept in the engine's memory only, never on disk.
- Not yet proven with real Claude: that resuming a finished session with the bundled binary carries the conversation over on the API key route, and what a resumed follow up costs. It needs a real-verify scenario with a real key.

## What the build settled (HeyClicky v1.0.53 parity, engine side, 19 Oct 2026)
- **Exact tools per flow.** The engine no longer gets the whole `claude_code` tool set. `runner/src/tools.ts` names what each flow uses, passed as the SDK's `tools` option: a task gets Read, Grep, Glob, Edit, Write, Bash, TaskStop, WebFetch, WebSearch, TodoWrite and ToolSearch; planning and Rescue's diagnosis get Read, Grep, Glob, TodoWrite and ExitPlanMode; Research gets those and WebSearch, WebFetch and ToolSearch; the second model review gets none. Left out on purpose: sub agents (`Agent`), Claude's own question box (`AskUserQuestion`), `EnterPlanMode`, the notebook editor and every scheduling, connector and hosted tool. WebSearch stays in tasks as before, but it is a paid search on the person's own key: the fix eval decides on it. The safety hook refuses most other built in tools with a plain reason (T05; the few it is not given but still judges by path as a second line of defence are named in `tools.ts`), and the real run harness checks `system/init` against the same list (`AGENT_TOOLS`). Not yet proven on a real run: that `system/init` lists exactly these, whether this binary has `TodoWrite` or only the `TaskCreate` family, whether a held back tool still needs ToolSearch, and how much the first round saves (technical_research.md section 20, question 26; the smoke test and the fix eval note the first round's tokens). Whether leaving out sub agents changes fix quality is for the fix eval rerun, when the founder says go.
- **Do what it can, then ask one short question.** The appended instructions now say: when only the person can give what is missing, do every part you can, then end the final message with one short question, and never make up a value. The runner reads the agent's last words (its text after its last tool, `runner/src/asks.ts`): when one of the last three sentences is a question, the task ends as needs you (`needs_you` in the task log, the agent's state `needsYou`). Its work is checked once and no fix round is started over the question, which would bury it and spend more of the person's money; the receipt carries the words (`said`, secrets hidden, at most 600 characters) and `asks`. The person's answer in the follow up box carries on the same conversation, told it is the answer. A step of a Drive plan that asks ends the plan there. If the checks pass anyway, the task is done and proven, and the question still shows on the receipt. To the real engine, a tool call is a turn of its own (`usedTool`), so words before it are never taken for the last ones.
- **Claude out of reach is named.** A turn that ends on a failed request comes back as a `success` result with `is_error` (technical_research.md pitfall 58). Before, such a task ended as done with nothing changed. Now it stops the round. A dropped connection (no answer at all, a name that does not resolve, a timeout) is `no_connection` and a busy or failing Claude on Anthropic's side (529, 5xx, overloaded) is `claude_busy` (`runner/src/reach.ts`); either is the task's status, the card says it in plain words with Try again, and Try again tells Claude truly how the last attempt ended. Problems with the key, the account or the request are never called a connection problem. Claude Code's own error message is never shown as the agent's words. After Stop, nothing is named this way. Not yet seen on a real Mac: what Claude Code sends with the Wi-Fi off, and how long it retries first (it says so in `system/api_retry` messages, which are not shown yet; a "still trying to reach Claude" line waits for that check). This costs nothing to check, since no request reaches Anthropic. The fast lane and the vision lane (Prompt help, Show me, Explain) still read results their own way and are not covered by this change (corrected in the review below: they are now).

## What the build settled (HeyClicky v1.0.53 parity, review fixes, 20 Oct 2026)
A review of the change above found these; each is fixed, with tests that failed first.
- **An offer is not a question.** Claude often ends with an offer ("Want me to add a test for it too?") or a check in ("Anything else?", "Does that look right?"). Counted as a question, such an ending skipped the fix round and the loop breaker over a failing check, and the card waited for an answer to an offer. Now `asks.ts` leaves offers and check ins out (a choice between two ways, "Should I use Resend or Postmark?", still counts), and the appended instructions say to put the one short question on its own last line and otherwise never to end on a question or an offer. After checks that failed, only a question that names something only the person has (their own value or account, or a choice) ends the task as needs you; any other question gets the fix round as before. With nothing changed, or after a fix round that changed nothing, any question still ends it as needs you.
- **Settings.** "Stop and wait when Claude asks me something" (`work.stopOnQuestion`, on) and "Let tasks search the web" (`work.webSearch`, on, as before) are in the registry (T16), read once when a task starts. Off, the first sends the failed checks back as before and only shows the question; off, the second leaves WebSearch out of a task's tools (`tools.ts` `taskTools`) and the hook refuses a search asked for anyway (T05). Research always has the web. Whether web search stays on by default is for the fix eval and the founder: each search is paid on the person's key.
- **No secrets asked for in chat.** The appended instructions no longer list "a key" among what Claude may ask for: Claude is told never to ask for a password, a key or any other secret, and to say which setting is needed and where (the project's `.env`, or the host's settings) so the person adds it themselves. An answer is never the task's name or goal: the task it starts is named "Answer to: " and the question (`tasks.db`, What I did), its goal stays the task's own, and anything in the answer that looks like a key is hidden before Claude is sent it (its conversation is saved).
- **Every failed request is named, not only Claude out of reach.** A refused key or sign in, no credit, too many requests, an account Anthropic holds back, a request Claude cannot take, a model the account lacks and a reply cut at its output limit stop the round as `claude_stopped:<kind>` (`reach.ts` `turnStop`), and the card says each in plain words (`S.claudeStopped`), never in Claude Code's own (which names its own `/login`) and with Try again only where it can help. A kind this version does not know is `unknown`, said plainly too. Claude Code's message about a reply cut at its output limit is its own ("API Error: Claude's response exceeded the 32000 output token maximum...", read from the pinned binary), so it is never the agent's words; the turn finishes if Claude Code carries on, and stops, named, if it ends as an error.
- **A bare timeout is not a dropped connection** when the run stopped by itself (`error_during_execution`): only a network marker (a connection error, ENOTFOUND, EAI_AGAIN, ECONN..., ETIMEDOUT, fetch failed) names it so, since a sandbox or a hook can time out with the Mac online. A request to Claude that only says it timed out is still a dropped connection.
- **The lanes too.** The fast lane (Prompt help, Explain, the error explainer, Draw it for me) and the vision lane (Show me, looking at a picture added to a request) read failed requests the same way: Claude Code's message is never the improved prompt, the explanation or a point, and the request fails, named, so nothing can be pasted back.
- **No Try again where there is none.** Planning, Rescue's look, Research, the lanes and the look at a picture have no Try again, so their stops are marked "(ask again)" (`reach.ts` `withoutTryAgain`) and the card says to ask again (`S.noConnectionAsk`, `S.claudeBusyAsk`), never pointing at a button that is not there or at an older task's.
- **Sub agents are refused.** `Agent` and its old name `Task` were still allowed in the hook with no card. They are refused now with a plain reason (T05).
- **EndConversation in system/init.** The tools reference says a tools list cannot remove `EndConversation` while any other tool remains, so every agent session would list it and the real run harness would have refused every agent case. It is accepted in an agent session's `system/init` (`ALWAYS_LISTED`), never named in `tools`, and still refused if called. A lane that names no tools may still list none.
- Not proven on a real Mac: all of the above uses fakes. The words and status Claude Code really sends for each failed request (a key that is wrong, no credit, the Wi-Fi off) and whether a reply cut at its output limit ends the turn as an error are [verify] items for a founder session; a wrong key and the Wi-Fi off cost nothing.

## What the build settled (audit fixes, 20 Oct 2026)
Found by the audit of 20 Oct 2026 and checked against the code; each is fixed, with tests that failed first.
- **A stopped round is still counted.** A round's cost arrives only in its final result, and Stop, Stop everything and a Drive pause end Claude Code's process, so no result came and the round was never booked (the daily limit, the receipt, the task log and a plan's budget all missed it). The engine now keeps a running estimate of each round from the token counts in Claude's replies (each request counted once, by its message id, at list price; a model the table does not know at the dearest current list price, T10) and books it when the round ends without a result, however it ends (`EngineOptions.unbilled`). A result replaces the estimate. A turn that arrives just after Stop is booked before the stop is noticed. The second reviewer's cost is booked the same way, and when it stops on its limit. [verify] Whether a conversation continued after such a stop carries the stopped round's cost in its saved total is not known: if it does, that round is counted twice, never missed. The SDK's `interrupt()`, which might end the turn with a result, is not used: it needs a real run first.
- **A stop is a stop, whatever the engine says.** An error result that comes as the run is being stopped (`error_during_execution` after Stop) is booked and ends the task as stopped, not as an engine error, and a paused plan waits instead of ending (tasks, Rescue, Research, planning).
- **Take the wheel and the loop card.** A hand edit, a pause key or Undo while a Drive step's loop card waits no longer pauses the plan (the card is already the question; before, the page hid the card on the pause and the plan waited on it for good). A pause during a Try a different approach run waits and carries on with the step, as a pause in a step's first run does. A Stop or a pause that lands while a round's after state is saved ends it as stopped, never as done with no check, so a paused plan runs the step again and checks it. A fix round that ended early still has its files on the receipt (the after state is saved again before the task ends), so the receipt names every file Undo changes. An approval card open when a step is paused, stopped or Stop everything is pressed is settled at once as cancelled, so a late Allow runs nothing and no card is left with nothing behind it; what was allowed for the rest of the task stays allowed across a pause.

## Revisit if
Anthropic gives written terms for managed credits, which need a Companion owned loop on the Messages API (section 20, question 2; product_research.md section 15, point 4). A routine SDK upgrade is not a revisit.

## What the build settled (second audit, runner fixes, 20 Oct 2026)
Each is fixed with a test that failed first (`runner/test/audit2-runner.test.ts` and the tests named below).
- **More habitual endings are not questions** (`asks.ts`): "Would you like to ...", "Do you want to ...", "Want to ...", "Ready to ...", "Shall we ...", "Should we ..." and check ins such as "Is that clear?", "Have I covered everything?" and "Did it work for you?". A choice between two named things still counts. A question Claude answers itself in the next sentences ("Is the build passing? Yes it passes.") does not count; one followed only by where the answer lives, or that Claude waits, still does. "Should I delete ...?", "Can I overwrite ...?" and "Should I use your ...?" (an `I` asking before something destructive, going out or theirs) are questions, not offers, and name something only the person has.
- **The receipt keeps the question.** For words that ask the person, a message over 600 characters keeps its end (the question is the last line) with a leading "…", in the engine and in the page (`saidOf`); any other message keeps its start.
- **A Drive step that passes its checks but ends on a question** ends the plan there as needs you, as a step that changed nothing already did. A single task stays done, with the question on its receipt.
- **Where was I** counts tasks that ended as needs you (until a newer task of that agent in that project answers them) in "waiting for you", and names no connection, Claude busy and the turn limit as stopped and an error as not done.
- **Put it online runs the checks again** when the last check was not a clean pass (gaps, a failure, nothing to check), so a fix in Settings or on the Mac is picked up without a file changing. Only a pass on an unchanged project is reused.
- **A project's own check settings stay with the project** when the person switches folder: the engine keeps the latest values for every project the shell has named (at most 50), so work still running in the folder just left reads its own.
- **The engine starts even if its task log or spending count cannot be written** (a full disk, a read-only file): both fall back to memory and say so. The spending count keeps counting in memory if a later write fails, so the daily limit still guards. The folder for undo points is made without stopping the start.
- **A task's Undo point is on its row from the start**, so a task cut short by a crash or a quit still shows it after the restart (the Before snapshot is written with `log.start`; `finish` keeps it when it has no receipt).
- **A damaged `memory-settings.json` fails closed**: learning is paused, the file is kept as `memory-settings.damaged.json`, the memory page says so, and turning learning back on starts a new file. Only a missing file means the usual choices.
- **Careful writes in the person's project** (`runner/src/atomic.ts`): the shared AGENTS.md and CLAUDE.md are never replaced or written through when either is a link, and keep their permissions; every small file Companion writes removes its temporary file when the write fails and sweeps old ones; a `ships.json` that cannot be understood is kept as `ships.damaged.json` before a new record is written; a stale `refs/cp/N.lock` and stray temporary files from a killed snapshot are cleared before the next snapshot.
- **Planning accepts the plan through `ExitPlanMode`**: in plan mode Claude hands the plan back that way, so the readonly flows let that one tool through (it changes nothing) and read its `plan` as the answer. [verify] on a real run that the hook receives it with the plan in `plan`.
- **Lessons**: a saved place for a lesson whose steps changed is thrown away and the start is a new one (it follows "Lessons start where you are"); the Vercel lesson no longer promises that opening it again reaches names past the twelfth. The four check practices also protect `package.json`, so a fix cannot pass by changing the test command. A start script chosen in Settings that `.claude/launch.json` overrides is now said as a gap.
