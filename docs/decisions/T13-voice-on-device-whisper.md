# T13. Voice transcribed on the device with Whisper

- **Status:** Accepted from research; open items checked in M0 spike (f), or in M2 if the founder picks the lean M0 plan. Updated 7 Oct 2026 after desk research and review.
- **Date:** 2026-10-06
- **Source:** technical_research.md section 1, row 13; section 15 (also sections 18, 19 and 20); M0-desk-research-details.md section (f)
- **Related:** F07, F11, T01

## Decision
Voice uses on device Whisper (whisper.cpp through Rust bindings) behind a hold to talk hotkey. No cloud speech.

## Why
- Claude takes images, PDFs and text, not audio (section 15).
- Claude Code's own `/voice` dictation streams audio to Anthropic, needs a claude.ai login, does not work with an API key, and is a terminal feature, not an SDK call (section 15).
- No per minute cost, and the same code runs on Windows. It covers about 99 languages including Hindi (section 15).
- It integrates an existing open model; it is not a voice engine of our own (product_research.md section 4).

## Alternatives considered
- Cloud speech to text, or a voice engine of our own: dropped because of per minute cost (product_research.md section 11).
- Claude Code's own dictation: needs a claude.ai login.
- Apple SpeechAnalyzer and SpeechTranscriber: need macOS 26 and launched with about 10 languages, no Hindi.
- Windows built in dictation: its grammar runs on a Microsoft web service.

## What this means for the build
Details are in technical_research.md section 15. Rules a coding agent must never miss:
- Default model: `base` or `small`, quantized (for example base-q5_1 about 57 MiB, small-q5_1 about 181 MiB; full precision base 142 MiB, small 466 MiB). It downloads when the user turns voice on, never bundled in the DMG.
- Read Handy (MIT, v0.9.8, Tauri, React and Rust) before writing the voice module. Use the Tauri global shortcut plugin, which needs no permission, not Handy's default `handy-keys` event tap, which needs Accessibility.
- Key down opens the microphone and the character shows Listening; key up closes it. The transcript appears in the ask box. No wake word. The kill switch hotkey also closes the microphone.
- The hotkey is a normal key plus modifiers: the permission free Carbon path cannot register fn or a modifier held alone.
- Add `NSMicrophoneUsageDescription` to `Info.plist` and `com.apple.security.device.audio-input` to the entitlements file, because Tauri turns on the hardened runtime. Ask on first use; treat all zero buffers as "microphone blocked".
- Recovery for a missing microphone entry: `tccutil reset Microphone <Companion bundle id>`, never without the bundle id (that resets every app on the Mac), then a full quit and relaunch.
- The ask box accepts paste and never swallows Cmd+V, so Wispr Flow and macOS Dictation work. Test both.
- Speaking back is off by default; the opt in uses `AVSpeechSynthesizer` system voices.
- Spike (f) passes when hold to talk gives text in under about one second after release for a short sentence with `base` (section 18).

## Settled by the build (9 Oct 2026)
- whisper-rs 0.16.0 with Metal builds and runs on this Mac (macOS 27, Apple Silicon). The base model (147,951,465 bytes, SHA-256 60ed5bc3...2efe, checked against Hugging Face's own record) is downloaded once into Companion's folder by the Mac's own `curl` and kept only if size and fingerprint match.
- A spoken sentence made with the Mac's `say` came back word for word. Loading the model takes a few seconds, so it is loaded while the person is still holding the keys; transcribing a 3 second sentence then takes about 0.18 seconds (target was about 1 second). The model is let go after five idle minutes.
- The global shortcut plugin reports key down and key up, so hold to talk needs no permission beyond the microphone. Default keys: Control, Option, Command and V. (Changed by F18 on 17 Oct 2026: two keys, Option and Space by default, with a short list of other chords in Settings; `talkkeys.rs`.)

## Settled by the build (17 Oct 2026, M11 wave 4 item 2: voice settings)
Build details inside this record's decision, not changes to it. Rules in `voiceset.rs` and `voicewords.rs`, tested without a microphone, a speaker or any sound; Settings rows in Home's Settings tab, Talking and listening.
- **Kept on this Mac** in `voice.json` in Companion's folder (delete everything removes it with the other settings): the voice, the speed, the microphone and the language. A damaged or odd file gives the Mac's own choice for that part, never an error.
- **The voice.** Settings lists the Mac's installed voices (`AVSpeechSynthesisVoice speechVoices`: name, language, quality), the Mac's own language first, best quality first, without novelty or personal voices. Nothing picked means the Mac's own voice. A picked voice that is gone (removed in System Settings) is replaced by the best one in the same language, then the same language from another place, else the Mac's own, and Settings names which one is gone and what speaks instead. A Hear it button says one sample line, only when pressed.
- **The speed.** Five steps, 0.5x to 1.5x. Normal is the Mac's own default rate; half speed is halfway from it to `AVSpeechUtteranceMinimumSpeechRate`, one and a half times halfway to the maximum (`voiceset::rate_for`).
- **Speaking back stays off by default.** Two switches, both off until turned on: Speak to me (the short lines, as before) and Answer out loud when I ask by voice: the whole short answer (up to 600 characters; a longer one is said up to a sentence, then "The rest is on the card.") to a question sent while the box still held the words from hold to talk, for ten minutes and once, and only the answer of the kind asked: a Show me's lines for a Show me, the research answer for Research it, a finished task's result for a task. Only an answer new on the card counts, so an older one still shown never stands in for it, and a lesson's lines are never said whole. A rescue is started by its button, never by voice, so it is not said this way. The same rules as every spoken line: no secrets, no web addresses read out, never during a call, card only.
- **The Mac's sound off.** Spoken lines were always shown on the card too. Now, when the Mac is muted, its volume is at zero or no output device is there (read from Core Audio, read only, no permission), nothing is said, and the card says once "Your Mac's sound is off, so I am showing the words only."; Settings shows the same in its own words while it is off.
- **The microphone.** Settings lists the Mac's input devices (cpal, by Core Audio's lasting device id). Nothing picked means the Mac's default, read again at every press, so Companion follows it when it changes. A picked microphone that is not connected at a press means the default listens, with one plain line, said once each time it goes away. While the keys are held, a microphone that goes away (Bluetooth headphones switched off) is replaced by the picked one, else the default, else any other, never by itself again; one that reports a changed rate (cpal's `StreamInvalidated`; a Bluetooth headset switching to its microphone mode does) is opened again. cpal's `DeviceChanged` (rerouted, still running), an overload and anything else keep listening. At most four reopenings per hold; what was heard before is kept, and the card says in one line that another microphone took over or that the microphone went away. The light still comes first and the microphone still closes on let go, Stop everything or after a minute.
- **The project's own words.** Whisper's initial prompt gets a short list of the open project's names: package names from `package.json` (the only file opened, at most 512 KB, never a version, a script or any value), the setting names the project check reported (names only), then folder and file names up to three levels deep, breadth first, code file names first in each folder (at most 6 names from and 400 entries looked at in any one folder, 4000 entries in all; never pictures, fonts, sounds or videos, or anything inside `public`, `assets`, `static`, `images`, `icons` or `fonts`; never hidden files, `.env` files, names that sound private or anything inside a folder whose name does, links, or folders such as `node_modules`), at most 40 names and 320 characters, each checked by the secret checks. Only on this Mac; the log records how many words, never which. A transcript that only repeats the list in its order is not taken as what was said.
- **The language.** Automatic by default (the model tells which language it hears); a short list in Settings (English, Hindi, Spanish and 18 more) fixes it.

## Settled in review (18 Oct 2026, M11 wave 4 item 2)
A review of the voice settings found these; each is fixed with a test that failed first.
- **Nothing is said while hold to talk listens.** From just before the light comes on until the microphone closes (let go, Stop everything, the minute running out, or a microphone that would not start), a line or a whole reply that arrives is dropped and its words stay on the card; anything being said is cut off before the microphone opens. So the Mac's voice never plays into the open microphone and is never written into the box as the person's words.
- **A Show me asked by voice counts only its own answer.** It takes the request its "Finding it" names; only that request's lines are said whole. Point at the problem, the hint shown when Show me is pressed with an empty box, a window that changed and any other Show me never are. It ends with its answer (the click, Do it for me, an error, a missing permission, a window that changed), when another Show me takes the pointer, after ten minutes, and when anything is pressed (the hero key, Find the problem, Do it for me, a rescue, a lesson). Not when the pointer goes away: the last step said in words clears the pointer first and its words come after. A Show me asked by voice that could not find anything says so on the card only, unless Speak to me is on.
- **Show me's timing follows the speed.** Each step waits as long as its line takes at the picked speed (slower speeds wait longer, so a line is said whole before the next step's line cuts it off); faster speeds keep the normal wait, since how fast the Mac's voice really goes at each rate is not measured. With only Answer out loud on, the Show me asked by voice is timed as spoken. At its start the card reads only the saved speed (`voice_speed`); the voices and microphones are still listed only when Settings opens. The ring itself still fades after at most 8 seconds.
- **The microphone.** A problem it reports is taken in one step, so a microphone going away right after an overload is never erased (`voiceset::Trouble`). A reopen looks for a let go or Stop everything before each try and after one opens, and closes one that opened meanwhile at once, keeping nothing it heard (`voiceset::reopen_first`). A device's name is read without a panic; a device whose name cannot be read (it is going away) is left out of the list.
- **Settings' line about the project's words** now names the setting names too (never their values), as PRIVACY.md does.

A second review the same day found these; each is fixed with a test that failed first.
- **The project's words in a real project.** The folder walk went depth first with one budget and took names in visiting order, so a `public` folder of pictures (it sorts before `src`) filled the list with `product-0`, `product-1` and so on, and 4100 icons used the whole budget before `src` was read. It now goes breadth first, leaves out pictures, fonts, sounds and videos and never looks into asset folders, puts code file names first in each folder, and takes at most 6 names from and looks at most at 400 entries in any one folder, so `useAuth` and `CheckoutForm` still make the list next to 20 package names and 8 setting names.
- **An answer in another project is said.** A reply was known by its checkpoint alone, and each project's checkpoints start again at cp_0001, so the first task asked by voice after the practice fix was never answered out loud, and the question stayed open for the next pressed flow's answer. Replies are now known by project and checkpoint (or research note), the card forgets what it said and any open voice question when the project changes, and a typed follow up, Try again, the error explainer's Fix it and Let me try the next one count as pressed.
- **A picked microphone that will not open when the keys go down.** It gave an error ("I could not use the microphone"), though the default could listen. Now the start tries the picked one, then the one a loss would give (`voiceset::open_at_start`, the same order and the same look for a stop as a reopen), and the one plain line names the picked one.

## Settled by the build (19 Oct 2026, HeyClicky v1.0.53 parity)
Built and unit tested with fakes only; no microphone was opened and no app was launched.
- **With the lid closed, another microphone listens.** The Mac's own microphone is cut off in hardware with the lid closed, yet it can stay listed and stay the Mac's default, so a held talk recorded silence. The lid is read without a permission or a new library: no online display is the Mac's own screen (`CGGetOnlineDisplayList` and `CGDisplayIsBuiltin`, Core Graphics, already used). Which microphones are the Mac's own comes from Core Audio's transport type (built in, with input streams), read through Core Audio's own C functions as the sound already is, matched by Core Audio's id, never by a name (`voice_mac::lid_closed`, `builtin_input_uids`, `voiceset::unheard`). The headphone jack is built in too, so it is told apart (found in review the same day; a wired headset with the lid closed was passed over): a device counts as the Mac's own microphone only when its input data source in use is the internal microphone (`'imic'`; an Intel Mac switches its one built in microphone to `'emic'` for a headset), or, when it reports no data source, when Core Audio's id does not name the headphone jack (Apple silicon's jack is its own device) (`voiceset::own_mic`). Settings names the microphone that really listens with the lid closed, and says which one is off (`state_json` `micQuiet`, `lidOnly`). Such a microphone is passed over at the start, after a loss and when a picked one is it; it is never called "not connected". With no other microphone, one plain line says the lid is closed and to plug one in or pick another, before the light comes on, and nothing listens. No AppleClamshellState (that would need IOKit bindings, a new dependency).
- **Silence is never blamed on the permission when it is granted.** All zero samples now carry why (`voice::why_silent`): the permission only when macOS says it is not allowed; the lid when the Mac's own microphone listened with the lid closed; otherwise the microphone itself (plugged in, muted). The words are the page's (`S.voiceSilent`).
- **No beachball after sleep or a headset change.** `voice_settings`, `set_voice_settings` and `speak` run on the main thread, which every panel shares. The microphones and the sound are now read from Core Audio on a helper thread with a 300 ms limit (`voiceset::Recent`, `inputs_now`, `sound_reading`): a slow read gives the last answer (no microphones listed, or the sound counted as on, when nothing is known yet; the sound is never claimed off without a reading), its late answer is kept, and only one read runs at a time. The Mac's voices are still read on the main thread.
- **[verify]** on a real Mac: that the lid reading is right with an external display and the lid closed, and with the lid open; that it needs no permission; that the Mac's own microphone reports the built in transport type on Apple silicon and Intel; that sleep and wake, and AirPods connecting, with Settings open no longer freeze the panels.
- **[verify]** on a real Mac with the lid closed and a wired headset in the headphone jack (on Apple silicon and on an Intel Mac): that hold to talk listens with the headset, that the jack's device id and data source are what `own_mic` expects (Apple silicon `BuiltInHeadphoneInputDevice`, and whether its internal microphone reports `'imic'`), and that Settings names the headset.
- **A deliberate difference from HeyClicky.** HeyClicky sends spoken words as soon as the keys are let go. Companion puts them in the box and waits for Start, unless Send spoken words automatically is on (`talk.autoSend`), and even then words that mean wait or stop, a question about the screen, or words in another language wait. The same holds for a follow up by pointing, where the box is decided as the keys go down, not when the words come back.

## Open [verify] items
- **[verify]** the release event still fires when the user lets go of the modifier before the main key (with Option and Space: Option first), and whether a Space still held then types spaces into the app in front.
- **[verify] Launch blocker.** With ChatGPT, Raycast, Alfred or Superwhisper holding Option and Space, whether macOS refuses Companion's registration (then the launch notice shows and Settings greys the chord out) or both apps get it and only one receives the press. The global shortcut library registers without the exclusive flag (global-hotkey 0.8.0 passes options 0 to RegisterEventHotKey), so a refusal is expected only when the other app asked for the keys exclusively. If both get it, nothing in Companion notices: the launch check and the Settings free check (`keymap::free` since M11 wave 4, when every key became changeable; it was `talkkeys::free`) both rely on a refusal. Until this is settled, Settings, the first run and INSTALL.md name those three apps and tell the person to pick other keys if one stops opening or talking does nothing. The answer decides whether that warning is enough for the launch or the default must change.
- **[verify]** whether the Mac's hot key service repeats the press while the keys are held. Handled either way (`talkkeys::Held` ignores repeats), but the answer tells whether that code is needed.
- **[verify]** whether `SpeechTranscriber` supports Hindi on macOS 27; print `supportedLocales` on the founder's Mac.
- **[verify] Voice settings, on a real Mac (none of it was run: no app was opened, nothing was said, no microphone was used).** That the voice list shows the voices System Settings shows, without novelty voices, and Hear it uses the picked voice at the picked speed; that the five speeds sound evenly spaced and 0.5x and 1.5x are still pleasant (the mapping is linear in AVSpeechUtterance's rate, which is not linear to the ear); that muting, volume zero and unplugging headphones on a Mac mini with no speaker are read right (Core Audio's mute and volume on the default output; some devices report volume only per channel, some not at all and then count as on); that the microphone list names AirPods, USB and the built in microphone as macOS does; that switching AirPods off while holding the keys moves to the default and keeps the words said so far, and whether AirPods starting their microphone really reports a changed rate (then the reopen matters on every first press); that following the default needs nothing more than reading it at each press; that the project's words make "supabase", "vercel" and "useAuth" come out right (`cargo test -- --ignored project_words_round_trip`, which makes its audio with `say` into a file, plays nothing, and needs the model) and do not make the model write project names into short or unclear speech; and how long gathering the words takes in a big project (the cap is 4000 entries, gathered while the person talks); that holding the keys while a reply is due says nothing and writes nothing of it into the box; that pressing the keys just after switching AirPods off listens with the default and says so once (whether a gone microphone stays listed for a moment and then fails to open is a guess from cpal's behaviour); that no Show me line is cut off at 0.5x and the waits at 1.5x do not feel slow; and that listing the voices and microphones when Settings opens asks for no permission (it reads device names through Core Audio and never opens the microphone; rule 8 says the Microphone permission is asked only at the first hold to talk).
