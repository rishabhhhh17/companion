## Part 2: Second Look, the helper HeyClicky does not have

**The problem everyone with an LLM has:** the answer sounds sure and may be wrong, and you cannot tell. CEOs, founders, engineers and beginners all get burned the same way: a wrong number in a plan, a citation that does not exist, code that quietly misbehaves.

**What it does:** you select an AI answer in any app (or press the key with it on screen) and press a key. The light comes on first (rule 5). Within about ten seconds a card says one of three honest things:
- **Solid:** what it checked and how.
- **Check these:** the specific claims that look shaky, why, and what to verify, with a source when it found one.
- **I can't tell:** what it could not check. It never fakes certainty.

For numbers it redoes the arithmetic itself. For facts it searches and shows sources. For code it flags the lines that look risky and says what test would prove them. For quotes and citations it says which it could not find. Companion's character reacts (a nod, a squint), which is the fun: a small "caught one" moment, never a score or a streak (rule 16).

**Why us:** it is the same idea as the hero ("done means proven") turned on any AI answer, and the engine for it already exists: the second model review (it caught 5 of 5 risky changes with no false alarms on real Claude), the text read on a hotkey (T11), the web search lane with sources (Research), and the redaction rules.

**What it is not:** it does not decide what is true. It shows its work, and says so when it cannot tell.

**Rules it follows:** the selected text is read only on the person's key press with the light on (5, 8); nothing is stored; secrets are hidden before anything is sent (redact); a check costs pennies and shows its estimate (T10).

**How we know it works (before anyone sees it):** an eval of 100 AI answers, 50 with a known seeded mistake (a wrong number, an invented citation, an out of date fact, a subtle logic slip, a wrong code detail) and 50 correct. Measures: how many mistakes it catches, how often it cries wolf, and how often it says "I can't tell" when it should. Targets: catch at least 85%, false alarms at most 10%, and never confidently wrong. The real run needs credits; the corpus, the prompts, the engine and the scorer are built first, with stand ins, like the other eval sets. Real run cost estimate: about $1 to $2.

**The fun, later:** "Spot what the AI got wrong": the seeded answers from the eval turned into a practice game that teaches people to catch mistakes. It is also a shareable result card. Built after Second Look works.

A second question stops the plan again and the next answer carries it on from there. The answer is never a task's name: the task list shows "Step 1 of 3: ..." and a pasted key is hidden before Claude sees it.

## Audit round 3 (engine, 24 Oct 2026)

An adversarial read of the engine code added or changed from 22 to 24 Oct (the plan that carries on after a question, make me something and the shared files, the daily limit, Second Look, the direct lanes). Each bug below got a failing test first (`runner/test/audit-round3.test.ts`, 20 tests, all failing on the old code), then the smallest fix. Nothing was run on real Claude and nothing was spent.

**Fixed**
- **Second Look froze the whole engine on some text (high).** The sum and "from ... to ..." matchers could take 5 to 15 seconds on 12,000 characters of numbers and commas, and the engine does nothing else (not even Stop everything) while one runs. Numbers are now bounded and a number's commas must be thousands groups. The same bound is on the table totals.
- **Second Look called correct sums wrong (medium).** "30 + 45 + 75 = 150" (the real run's own example), "2 + 3 + 4 = 9", "10 - 3 - 2 = 5" and "4 + 2 × 3 = 10" were cut into pieces and reported as slips ("45 + 75 is 120, not 150"). A chain is now left alone, as are decimal commas ("1,5 + 2,5 = 4") and two years ("from 2020 to 2024 ... 12% growth").
- **A real finding was dropped as a retraction (medium).** "This function has no error handling" and "the sum is right; however the quote was never said" were read as the model changing its mind, shown as checked, and the answer could end up "solid". "No error" now counts only when it ends there or says where, and more words that mean something is still wrong keep a finding.
- **The checked answer could close its own fence (low).** The answer sat between `<<<` and `>>>`, so text with a `>>>` line could carry on as instructions. The fence is now new and unguessable every time. A long answer is also cut between whole characters, and a very long input is cut before anything runs on it.
- **Secret hiding slowed to a crawl on long runs of dots (medium).** `redact` took a time that grew with the square of the length on text like `a.a.a.` (2 seconds at 48,000 characters). The two patterns that did it are bounded. Named secrets in long names are still hidden.
- **Two spellings of one folder had two daily limits (medium).** `/proj` and `/proj/`, a "." step or a link to the folder were booked separately, so a folder could spend its limit once per spelling. The ledger now keys a folder by its real path (and still counts what an earlier version booked under the plain spelling).
- **A cost that is not a number (low).** A turn cost of NaN made a task's running total NaN, which never reaches its limit; a negative one gave money back. The real Claude engine cannot produce either, but a scripted or future engine could. Costs are now money above zero or nothing.
- **The key could follow a redirect (medium).** A redirect from the API address (or from the managed usage server) to another host was followed, and fetch drops `Authorization` but not `x-api-key`, so the key or the sign in token went there. Redirects are no longer followed on the direct lanes and the pointing lane. A streamed reply line that never ends is refused after 4 MB.
- **A made folder reached through a link (low).** `madeBySquibby` looked at the path as written, so the same folder opened through a link was not recognised and got the shared files written.

**Looked at, no bug found (with tests that already hold)**: a plan resumed after Undo, a new task, a restart (memory only) or in another project; two answers at once (the second is refused); the carried steps' approvals, write rules and budget; the answer kept out of task names, the ledger and events (also off the record); a question asked inside a carried step; the Second Look "never solid with a maths slip" rule; the managed base being https only and a plain origin; the key kept out of error messages; Stop mid request.

**Open (not confirmed, or a design choice)**
- A light call that is stopped or times out (Show me how, the error explainer, Second Look, Draw it) books nothing, and so does a streamed reply cut by an error event. The money is spent on the API side but we have no number to book. A hard fix would book the estimate from the request's input size.
- Two light calls started at the same moment can both pass the limit check; each is small and the next one is refused.
- On managed usage the token is read from the same Keychain slot as an API key. If a person had stored a real API key there first, it would be sent to the usage server. Settled by how the Mac app stores the token (not engine code).
- The text of a percentage claim (up to 40 characters) is repeated to the model after the fence in "already redone by code". It cannot change the verdict (the code decides that), but it is a place text from the answer sits outside the fence.

### Checked and held (no bug found)

By reading the code unless a run is named.

- **Injection through names.** The document's name is used only for its ending (`doc_of`, `ext_of`); Squibby's copy is always `in.<pdf|xlsx|docx|doc|rtf|odt>`. The PDF script is one constant; the two paths arrive as `argv` after `--`; unzip is only asked for names `part_ok` allows (under `xl/`, no pattern characters, no `..`, no dash first). `textutil` and `osascript` get argument lists, never a shell string, with `env_clear` and `PATH=/usr/bin:/bin`. A name with spaces, quotes, newlines, a leading dash, `..`, unicode tricks or 10,000 characters reaches none of them.
- **Local file inclusion through a document.** On this Mac a `.docx` with an external `altChunk` and an `INCLUDETEXT` field, an `.rtf` with `INCLUDETEXT`, and an HTML `.doc` with an iframe and an object all pointing at a local file gave none of that file's text, with and without `-noload`.
- **Temp folder.** Created 0700 under a per-read name, copy opened with `create_new` 0600, removed on drop (also on a timeout and an unwinding panic), a root that is a link is refused, the launch sweep only removes a real folder of that one name and never follows a link. The vet and the read are both on Squibby's own copy in that private folder, so there is no swap between them.
- **Tool caps.** Output is read in 64 KB pieces up to the cap, then the tool's process group is killed; a deflate bomb sheet of 264 MB (768 KB zipped) was read in 1.3 s and cut at 400 KB. A real Apple `.xlsx` (Numbers' own template) reads fine.
- **Core Audio and camera checks.** `quiet()` calls `CAMERA_CHECK_ON && camera_in_use()` and `MIC_CHECK_ON && mic_in_use_by_another_app()`; with the constants false the call is never made (no Core Audio, no AVFoundation), and nothing else calls `input_processes`. Switched on, it reads only process ids and whether an input runs; every failure is `None` and the sizes are bounded (4,096 processes), so no crash path was found. `showme::with_project` only adds the open folder to the engine command (for the daily limit), and only the engine's ledger uses it.
- **New commands.** `read_document`, `start_in_new_folder`, `list_made`, `open_made`, `reveal_made`, `trash_made` and `shared_files_state` are all Home only (`only_card` or the label check), none takes a path or a parent from a page (a folder name only, checked by `made::shown`), none is on the engine's allow list, and every registered command (92) is in `protocol/groups.json`. `trash_made` moves only to the Mac's Trash, never the open project, the folder that holds it, or anything while a task works or waits, and holds the new folder lock.
- **Case and unicode.** A "Cafe" and a "café" are different names on the Mac and the same one when only the case or the form differs: `destination` asks the real file system (`taken`), so it numbers around either; the undo history key is the path as made, so a Trash and a new folder of the same name still get "2".

### Not confirmed (suspicions with no failing test, left alone)

- A PDF that expands to gigabytes of text, or a `.docx` whose zip list lies, could use a lot of disk or memory for up to 30 s before the tool is ended. Cannot be built without a hostile PDF; the time limit is the guard.
- `sharedfiles::shared_file` checks that AGENTS.md is not a link and then reads it: a swap between the two would read through a link. The answer is only "does it contain our mark", so nothing leaves; it needs a second process of the same person. A `O_NOFOLLOW` open would close it.

- `reveal_made` spawns `/usr/bin/open -R` and never waits for it, so each press leaves a finished process until the app quits (the same pattern is used elsewhere).

## Audit round 3 (usage server and pages) (24 Oct 2026)

An adversarial read of `usage-proxy/` and of the page code added from 22 to 24 Oct 2026 (the dock character, What Squibby made, the shared files row, documents in the ask box, Make me something, the plan answer words). Every fix below has a test that failed first. Nothing was run against real Claude, the network, a key or a Dodo account, and no Rust was built (this Mac has no cmake), so the shell side of the shared fixtures was not run here.

**Fixed (each with a failing test first):**
- **A failing store could strand a running slot (usage-proxy/src/proxy.ts).** If booking the cost of a streamed reply threw, the user's running slot was never given back, so a flaky store would lock a user out after four such requests. The slot is now released in a `finally`.
- **A body with no length that never ends was read whole (proxy.ts).** The size limit was checked after the whole body was in memory. It is now read up to the limit and refused with 413 the moment it passes it.
- **The upstream address was not held to https and redirects were followed (proxy.ts).** Our Anthropic key travels in a header, and a fetch follows a redirect to another host with custom headers. The proxy now refuses to start on an address that is not https (loopback aside, for tests) and sends with `redirect: "manual"`.
- **`speed` and `service_tier` were forwarded (usage-proxy/src/filter.ts).** Squibby never sends them, and the price table counts the standard price only, so a faster or priority reply would be under counted. They are refused like `tool_choice`. Whether the live API prices them higher is from memory of the API, not checked today.
- **Two Dodo events for one person arriving together could land in the wrong order (usage-proxy/src/dodo.ts).** The check "is this older than the newest applied" and the save were separate steps, so an older, slower "active" could be saved after a newer "cancelled" and give back a plan. One person's events are now applied one after the other inside the handler. Across several server instances the store must do the same in one atomic step, as the README already says; that is still the real store's job.
- **The Dodo ledger of handled event ids grew for ever (dodo.ts, `MemoryDodoLedger`).** An id is now forgotten after 15 minutes (three times the signature window, after which a signed copy of the event cannot pass anyway). A real store should expire ids the same way.
- **Engine caps counted text before secrets were hidden (runner/src/attach.ts, `checkAttachments`).** Hiding a short secret makes text longer, and the page counts after hiding, but the engine counted before, so a request that skipped the page could pass the 100 KB and 200 KB caps by a third. It now counts the text that goes.
- **File names (attach.ts `baseName`, app/src/attachfiles.ts).** The Arabic letter mark, line and paragraph separators and the invisible "tag" characters (nothing on screen, but a model reads them) were not taken out of a name. And two notes (a file that could not be read, and the file past the twentieth in a drop) showed the raw name with its path and direction marks. Both now use the clean name.
- **A short folder size that stopped early said "At least about 1 MB" (app/src/made.ts).** It had not counted a megabyte, so it now says the size was not counted. The old test encoded the wrong sentence and was changed with it.

**Checked and held (nothing to fix):** tokens (only a SHA-256 hash is stored and looked up, the token is in no log, a real Anthropic key is never accepted, no timing path because the lookup is on the hash); headers (a fresh set is built, only a validated beta list and the version are taken from the client; no key, cookie, host or hop by hop header is forwarded); the path and method (exactly two paths, POST only, query text dropped except `beta=true`); the tools (one exact web search shape, `mcp_servers`, `container` and `tool_choice` refused); Stripe and Dodo signatures (constant time, five minute window, replay by id, unknown products grant nothing, a cancelled Dodo subscription drops to free at once); the switch (nothing is served at all unless the operator turns it on, and a provider setting of none has no webhook address); the streaming meter (a split chunk, a cut stream, an overlong line, text that mentions "usage" are all handled); the made folder names (the shell refuses any name with direction marks, control characters, a slash or a leading dot, so the page never gets one); the shell building a new folder's name; focus after the shared files button (Home's general focus return handles it); names, "Companion" and "Claude Code" in anything a person reads (none).

**Suspicions I could not confirm (no failing test, so not changed):**
- The `anthropic-beta` header is passed on from the client (characters checked only). A beta that changes the price (a longer context window, a longer cache life) would be under counted. Squibby's own lanes send no beta header, so refusing all of them is likely safe, but I could not prove no other caller needs one.
- A cache write with the one hour life is priced at the five minute rate in the table (about 1.6 times too low on those tokens). Bounded by the plan limit.
- A stream cut by the client is charged only for the output the client saw; Anthropic may have produced more before the cancel reached it.
- The budget is not reserved: a user at zero can start four requests at once, each as dear as one request can be (by the price table a 200 K token prompt on Opus 5.5 is $0.80 of input alone, plus up to 64 K tokens of output at $20 per million), so a Free user could pass the $0.20 day and $2 month limits once by a few dollars. Documented, bounded, not fixed.
- Stripe: `unpaid` keeps the plan as "past due" and `paused` changes nothing, and the entitlement has no event time for ordering, so a late "updated" could regrant after "deleted". An existing test says `unpaid` keeping the plan is the intent. Dodo is the chosen provider, so I left Stripe alone.
- Dodo: a person with two subscriptions (an upgrade bought as a second one) would drop to free when the first is cancelled, because the plan is per person, not per subscription. And if checkout metadata can be set by the buyer (a static payment link), a buyer could aim their payment at another person's id; whether Dodo allows that is not known.
- A made-folder confirm stays open if the folder becomes the open project meanwhile; the shell refuses the move, so nothing is lost.
- Rust: the shell's list of hidden direction characters in `made.rs plain_name` lacks the Arabic letter mark (U+061C). Not changed (no cargo run here).

**Not checked:** the Rust tests and the shared fixtures on the shell side, any screen on a Mac (VoiceOver included), the live Anthropic API, a real Dodo webhook, and a real store under many instances.
